# VoiceHub 技术设计

> VoiceHub 是单机运行的服务：管理音色库，向多台 TTS 引擎转发合成请求，并以「生产方插件」的形式提供有声书生产。
> 本文描述当前实现的结构与契约。请求参数的完整定义见 [request-spec.md](request-spec.md)，引擎接入契约与步骤见 [engine-integration.md](engine-integration.md)，有声书流水线见 [audiobook-flow.md](audiobook-flow.md)，界面与代码约束见 [AGENTS.md](../AGENTS.md)。

## 1. 范围

**提供**：本地与平台音色的统一管理、样例试听与编辑、多引擎合成中转、语音识别、有声书生产（分章 → 拆句 → 分析 → 逐行合成 → 合并）。

**不提供**：TTS / ASR 模型服务本体、模型权重下载、多用户与权限体系、云同步。云端引擎由用户提供密钥，本机引擎由用户自行启动推理服务。

## 2. 总体架构

```
浏览器（Vue 3 SPA）
    │  /api/v1
FastAPI（单进程）
    ├─ api/          HTTP 层：校验、序列化、鉴权
    ├─ usecase/      用例：音色库、引擎、合成网关、识别、对话模型、生产方
    ├─ domain/       模型与纯规则（零 IO）
    ├─ infra/        文件系统、SQLite、sidecar、配置、ffmpeg、日志
    ├─ engines/      TTS 与 ASR 插件（builtin/<key>/）
    ├─ llm/          对话模型插件（builtin/<key>/）
    ├─ embedding/    语义召回插件（builtin/<key>/）
    └─ producers/    生产方插件（builtin/audiobook/、audiocpp/）
```

- 后端同时托管前端构建产物，启动一个进程即可使用。
- 分层依赖单向：`api → usecase → domain / infra`；插件只依赖各自域的基类。
- 数据库为 SQLite：`hub.db` 存音色索引与配置状态；每个生产方另有自己的项目库。

### 目录

| 路径 | 内容 |
|---|---|
| `app/` | 后端（FastAPI） |
| `app/engines/builtin/` | TTS 与 ASR 插件，一台一个目录 |
| `app/llm/builtin/` | 对话模型插件 |
| `app/producers/builtin/` | 生产方插件，目前为 `audiobook`、`audiocpp` |
| `web/` | Vue 3 + TypeScript + Vite 前端 |

| `docs/` | 设计、请求规范、流水线文档 |
| `tests/` | pytest |

## 3. 音色模型

### 3.1 扫描规则

用户可配置多个扫描根。规则由 `domain/scanner.py` 唯一实现：

1. 递归遍历；某一层**直接包含音频文件**（`.wav` / `.mp3` / `.flac` / `.m4a` / `.ogg`）的文件夹即为一条音色，文件夹名即音色名，不再深入子目录。
2. 该文件夹的上一级为分类；上一级是扫描根时分类为空。
3. 扫描根下平铺的音频文件各为一条音色，音色名为文件名去后缀。
4. 音色身份 = 文件夹绝对路径的散列。不同根下的同名音色是两条独立条目。
5. 扫描只读：不创建、不修改任何文件。`voice.json` 只在**编辑元信息**与**音频落盘**（`infra/archive.record_sample`）时写，扫描不碰。

### 3.2 增量扫描

`infra/walker.py` 在一次 `os.scandir` 中取得文件名、大小与 `mtime_ns`，生成目录指纹存入 `voices.scan_stamp`。下次扫描指纹未变时整条复用索引，不读 sidecar、不重建模型、不写库。音频时长另有 `probe_cache`（路径 + 大小 + mtime → 秒）。时长为 `0.0` 的记录不复用，以便后续重试。

`voice.json` 的每条样例还带一份时长备份 `duration` + `bytes`（写它的那个文件的字节数）。扫描先用 `probe_cache`；没命中时若字节数对得上（或缓存整体为空、老 sidecar 又没记字节数）就直接采用备份，不再起 ffprobe——改名、搬家、库重建时尤其值；字节数对不上说明音频换过，照常量真的。备份在**落盘那一刻**写（`archive.record_sample`），改样例文字时原样带着走。

### 3.3 样例文本

优先级从高到低：

1. `voice.json` 中用户编辑过的 `text`；
2. 与音频同名的 `.txt`（`开心.wav` ↔ `开心.txt`）；
3. 文件夹内 `list.txt`（每行 `音频名|文本`）。

界面编辑只写入 `voice.json`，不改训练用 `.txt`。说话内容同时作为参考文本随样例音频发给引擎，是一等字段。

### 3.4 存储分工

| 数据 | 位置 |
|---|---|
| 本地音色元数据、每条样例的文本/情绪/标签/时长备份、主样例 | 音色文件夹内 `voice.json` |
| 收藏/隐藏 | 正本在 `voice.json`（跟着文件夹走），`hub.db` 存副本并把侧边栏的筛选跑在库里 |
| 扫描根、平台音色条目、引擎配置 | 服务数据目录（`config.json`、`hub.db`） |
| 查询索引 | `hub.db`，可由扫描重建 |

`voice.json` 只写用户改过的字段，全部可缺省；`samples` 按键增量合并。写入采用临时文件 + rename，先写 sidecar 再更新索引；sidecar 写失败则接口失败。

### 3.5 数据模型

| 字段 | 说明 |
|---|---|
| `id` | 本地音色：路径散列；平台音色：`<engine>:<voice_id>` |
| `source` | `local` 或平台 key |
| `name` / `display` | 名称；显示名回落规则为 `display or name` |
| `category` | 分类：本地为上级文件夹名，平台为平台分类 |
| `gender` / `age` / `language` | 性别、年龄感、语言（BCP-47 主语言子标签） |
| `tags` | 多值特点词 |
| `folder` / `cover` | 本地音色文件夹与封面文件名 |
| `origin_id` | 该文件夹归属的平台音色 id（从 sidecar 的 `origin` 读入） |
| `samples` | 详情接口返回：文件名、文本、情绪、标签、时长、是否主样例 |

性别、年龄感、语言的候选词表只在后端定义，随 `/api/v1/tree` 下发；角色卡的两组固定标签（`语调` / `音色`）也随 `/api/v1/tree` 下发，选中的与自填词一样落进 `tags`——筛选、AI 匹配、配色不必另认一套。情绪候选来自生效词表（`/api/v1/vocab`，带 `groups` 分组），创作页总览同样带上分组。前端不保存第二份。候选不是白名单：词表外的值原样保留并显示。设置页「词表」只记用户差别（删除 `hidden` / 默认条目改名 `renamed` / 自定义 `custom`）；删除只改候选表，不动项目行上已经写下的标签。AI 辅助提示词（对话分析预设、匹配音色、角色画像、文本转正则）也由后端存默认与覆盖，设置页编辑，各任务运行时读同一份生效值。

主样例判定顺序：`voice.json` 的 `main_sample` → 文件名含「默认 / default / 主」→ 文件名升序第一条。`默认` 等词不计为情绪。

## 4. 插件体系

四类插件域共用同一套宿主规则：一个目录一个插件、自声明配置模型、配置存服务端、机密读取时掩码、自带图标与路由。

| 域 | 基类 | 发现 | 职责 |
|---|---|---|---|
| TTS 引擎 | `engines/base.py` | `builtin/<key>/` + `voicehub.engines` | 文本 → 音频 |
| 语音识别 | `engines/asr_base.py` | `builtin/<key>/` + `voicehub.asr` | 音频 → 文本 |
| 对话模型 | `llm/base.py` | `builtin/<key>/` + `voicehub.llm` | 消息 → 消息 |
| 生产方 | `producers/base.py` | `builtin/<key>/` + `voicehub.producers` | 源文本 → 章节 → 音频 → 成品 |

向量模型（`app/embedding/`）是独立能力：发现组为 `voicehub.embeddings`，不共用上表的配置存取与机密掩码，不计入四类插件域（发现机制仍与其他域同一套）。

- **发现机制**：以上五处的「怎么找」只有一份实现——`app/infra/plugin_registry.py`。各域注册表只声明基类、内置包位置与插件文件（写在子包 `__init__` 还是 `plugin.py`），不再各写一遍扫描与缓存。
- **发现顺序**：entry points 优先于内置目录，第三方包可覆盖同名内置插件。插件导入或构造失败时跳过并记一条 warning，不影响其他插件。
- **配置**：`settings_schema()` 返回 pydantic 模型，前端按 `model_json_schema()` 渲染表单。`""` 表示不修改；`{"_clear": [...]}` 清除机密；`{"_reset": true}` 恢复插件默认（机密保留）。
- **前端不识别厂商**：字段名、控件类型、候选值、能力说明、页签、参数映射均由后端下发。前端代码中不出现引擎 key 分支。
- **依赖方向**：插件依赖宿主契约；宿主不认识任何具体插件。删除插件目录即删除对应功能。

## 5. TTS 引擎

### 5.0 启用与停用

**发现一台插件不等于它在用**。发现到的引擎全部留在适配清单里（`GET /engines/catalog`），而左栏、生成页勾选、生产方候选、`engines_for_voice` 与合成网关只认**已启用**的那几台（`GET /engines`）。启用清单是 `config.json` 的 `engines_enabled`；缺这个键（升级前的配置）时按"用过的"推导：有配置段、有通道、有保存目录、是当前识别引擎，都算用过。推导结果不落盘，用户第一次启停时才写成明确清单。

界面上只有**一个控件语言：开关**。清单里每台一行、右端一个开关，开 = 启用、关 = 停用。开关只在引擎清单里；引擎面板不再重复一颗，抬头留给文档入口。没有"添加 / 删除"两套动作——那是同一个开关的两态。

各出口也只有一个字段：``enabled``（``True`` = 在用）。适配清单、引擎自描述、左栏树行都带它，极性一致；不要再另出一套 ``disabled``，两个字段并存迟早会有一处读反。

- 保存设置顺手启用（填了配置就等于在用），省一次"先开关、再配置"的往返。
- 停用不动配置，也不动库内音色：配置留着，音色在左栏单列一段「已停用的引擎」，点一下只看它们。删配置是另一件事，不在停用里做。
- 停用的引擎不能被调用：网关回 `engine_not_enabled`（400），不是 `engine_not_found`——前者一步就能解决。
- **口味与词表按已启用收束，引导指令预设例外**：语气词「通用」只在已启用那几台之间求交集；分配弹窗的引擎候选、健康检查的引擎状态、文本阶段的标签渲染，都只认已启用。引导指令预设是自由文本的"现成说法"，按**全部已发现**引擎的 `instructions.json` 合并，与启停无关——停一台不该让候选凭空少一段，发给不认这一格的引擎也只是装配时被剔掉。
- **生产方在计划期就收**：音色指向的引擎被停用时，这些行在生成计划里摘掉、按引擎记一条「N 行所属引擎已停用，已跳过」；不留在队列里逐行撞网关——那会变成一万行失败配一个原因。停用因此不损坏项目：重新启用后同一批行照旧能排进计划。
- **运行期同样只停不停说**：计划算完到跑完之间开关仍可能被关，批内第一行撞上 `engine_not_enabled` 就停掉这台引擎的剩余行，与「连不上」同一处置（`CODES_ENGINE_UNAVAILABLE`）：剩余行不发请求、不写行错误，留在待生成，日志与任务说明各一条。
- 库与归档仍按**全部**插件看：`engine_roots()` 要把停用引擎的保存目录继续从扫描根里摘掉，`generated_sample_path()` 也要找得到停用引擎留下的产物——停用不该让已有文件"消失"。同理，行参数面板按**插件身份**取引擎（回答"它能调什么"），不看启停：停用之后那些行仍要看得见自己的参数面。
- 识别引擎不在这套清单里：识别的"当前那台"由 `config.asr_engine` 单独回答。

### 5.1 能力与形态

`Capabilities` 声明：部署形态（`cloud` / `local`）、音色清单、音色克隆、音色设计、试听合成、参考音频、情绪控制、单次文本上限。界面按声明渲染，不按引擎名判断。

语言面也是 `Capabilities` 的事实格：`languages`（能念的语言代码）、`cross_lingual`（音色与正文能不能是两种语言）、`dialects`（能念的方言）、`language_note`（覆盖比官方窄在哪）、`language_hint`（已支持的方言语种实际口音由什么决定）。展示分两处：`cross_lingual` 是能力，只在「能力」卡里出一枚「跨语言合成」标签、不写解释；`languages` / `dialects` 是清单，单列「支持语言」一栏，语言那一行跳过同时算方言的词（粤语），`language_note` 作该栏的副标题。`describe()` 的 `languages` 块（`codes` / `supported_codes` / `dialect_codes` / `items` / `dialects` / `cross_lingual` / `note` / `hint`）与界面同源：`supported_codes` 把方言说法归一成代码，是网关剔语言与生成页列出「不支持所选语言」引擎的唯一判据；`dialect_codes` 是其中已支持的方言代码，选到这些格且引擎给了 `hint` 时，生成页在音频条下提示实际口音由参考音频决定（如 OmniVoice 的粤语）。不支持的语种仍按不支持列出并剔掉，不能拿 `hint` 抵掉。不在声明里的正文/参考语言按不指定发送，不拦整段合成。

设计音色没有平台音色 id：描述存入库内音色的 `payload.design_prompt`，网关透传给插件，每次合成按描述重新生成；平台不保存音色。它不绑定引擎——描述是自然语言，凡声明了 `voice_design` 的引擎都能按它生成，用哪台由用户在合成页选。库里的这一行与普通音色同表（`voices`），只是 `folder` 为空、`payload` 里多这一句；左栏因此单独分出一组「设计音色」。创建窗口不问引擎：各家都只是「按描述现场生成」，只取哪台声明了能力，来源优先记成生成页已勾选的那台。描述可由对话模型现写（`POST /voices/design-prompt`，提示词在 `usecase/voice_design.py`）：创建窗口拿名称与已写的描述作输入；创作页由音色分配在同一次回复里直接写出最终描述，落库前只做清洗与截断；用户自己写的描述视为定稿，不改写。

### 5.2 音色通道

「这台引擎使用哪些音色、如何供给」由通道配置决定，默认值由能力推导：

| 通道 | 语义 | 默认用于 |
|---|---|---|
| `own` | 引擎有自有音色清单或克隆；入库后与本地音色统一管理，合成使用平台音色 id | 有 `voice_listing` 的引擎 |
| `library` | 引擎无自有音色；合成时以参考音频 + 参考文本提供音色库中的音色 | 无 `voice_listing` 且有 `reference_audio` 的引擎 |

允许的通道是能力的子集，越界或非法值回落到默认通道。用户修改存入 `config.channels[key]`，与 `config.engines[key]` 分开保存，避免保存密钥时覆盖通道。默认值不落盘。

### 5.2.1 音色凭据（谁决定这次发什么）

一条音色落到某台引擎上，这次请求带什么由 `app/domain/credential.py` 的 `credential_of(voice, engine_key)` 判定，结果是四种之一：

| 凭据 | 含义 | 出现条件 |
|---|---|---|
| `reference` | 带一段音频，引擎按它复刻 | 本地音色；复刻音色（`payload.ref_audio`）；跨平台且有样例的平台音色 |
| `design` | 带一句描述，引擎现场设计 | 设计音色（哪台引擎都能用，能力不够的那些由 `engines_for_voice` 筛掉） |
| `platform` | 带平台音色 id | 预置音色回到自己的平台 |
| `none` | 落不到这台引擎上，发请求之前报错 | 跨平台又没样例；本地音色没样例 |

两条硬规则：

- **预置音色一律发平台音色 id**，不拿它自己的样例去复刻；通道配置不改变这一条。
- **样例是通用素材**：别的平台留下的音频，任何接受参考音频的引擎都能拿来复刻。

这是唯一判定。网关按它组装请求，分配弹窗按它给候选（`engines_for_voice` 只多一道"就绪"过滤），前端按下发的 `voice.engines` 摆选项——生产者与前端不得自行按 `capabilities()` 再推一遍，否则选项会与合成分叉。一致性由 `tests/test_credential.py` 的矩阵锁住。

### 5.3 生成物归属

- 生成物按音色归档：`<保存目录>/<音色名>/<时间戳>-<序号>.<格式>`，同目录 sidecar 记录 `origin.voice_id`。
- 读回时先按 id、再按名称匹配；平台音色与本地音色的生成物都挂回各自音色，不新增同名条目。
- 每台引擎可单独配置保存目录（`config.engine_outputs[key]`）；留空时使用全局生成目录下的引擎子目录。
- 引擎保存目录不作为扫描根。若用户把生成目录指进音色库，扫描时跳过该目录，避免重复条目。

### 5.4 参数映射

每台引擎在 `mapping.py` 中声明统一参数到原生请求体的映射：

- `ParamMapping(source, target, required=, transform=, note=, warning=)`；
- 缺省项不发送（`skip_empty`），以区分「未要求」与「要求为 0」；
- 必需项缺失时在装配阶段报错；
- 无法换算的值报错，不静默丢弃；
- 无落点的项由 `unsupported()` 返回原因，界面显示「—」。

## 6. 合成请求

统一请求为「一段文本 + 一个音色 + 一组参数」。完整字段、单位、区间与候选见 [request-spec.md](request-spec.md)。

- 规范定义在 `domain/request_spec.py`，`GET /api/v1/spec` 下发；前端按规范渲染表单，新增参数不改前端。
- 语言、静默、输出三组在界面上默认收起，值照常生效。
- 正文支持统一语气词标记：`[[笑]]`、`[[停顿:0.4]]`。各引擎通过 `mark_map` 登记自己支持的标签；翻译由网关在发出前统一执行一次（`EnginePlugin.prepare_text`），不支持的标签在那里从正文删除。「通用」分组由核心按所有支持标签的引擎取交集，认任意标签的引擎按全集计入。
- 读音替换在网关内完成：`pronunciations.json` 提供「词 → 同音词」，按最长词优先替换，方括号标记不参与。替换只作用于发给引擎的正文，归档与字幕保留原文。

### 持久化模式

`POST /api/v1/synthesize` 的 `persist` 决定音频去向：

| 值 | 行为 | 使用方 |
|---|---|---|
| `none`（默认） | 不落盘；响应体为音频字节，元数据在 `X-VoiceHub-Meta` | 第三方调用 |
| `cache` | 落缓存目录，返回 `audio_url` | 生成页扇出 |
| `sample` | 落该引擎的音色保存目录，并登记为该音色的样例 | 音色详情的「生成样例」 |

## 7. 语音识别

识别是与 TTS 方向相反的插件域，契约在 `engines/asr_base.py`：`transcribe` / `readiness` / 能力自描述。

- **识别插件 `qwen3_asr`**：连接一台 Qwen3-ASR 服务（默认 `http://127.0.0.1:18999`）。插件只包含客户端实现，模型与服务由用户自行部署；核心不下载权重。
- **识别插件 `sense_asr`**：连接一台 SenseVoice-Small 服务（audio.cpp 的 `sense_asr` 族，默认 `http://127.0.0.1:18102`）。与 Qwen3-ASR 共用 OpenAI 兼容客户端；注意 offline 的 `sense_asr` 需要 Silero VAD 资产，默认用 streaming 的 `sense-asr`。
- **输入**：非 WAV 音频先由 ffmpeg 转为 16 kHz 单声道 WAV，再以 multipart 上传。单段识别不使用引擎的流式接口。
- **流式识别**（`/api/v1/asr/stream`，WebSocket）：用于麦克风常开的连续对话。客户端先发文本 `{"type":"start","sample_rate":...}`（浏览器 `AudioContext` 的实际采样率，服务端统一重采样到 16 kHz），之后发二进制 int16 单声道 PCM，收尾发 `{"type":"stop"}`；服务端推 `ready` / `speech` / `partial` / `segment` / `error` / `done`。分段由核心的 Silero VAD 状态机完成（`usecase/asr_stream.py`）：静音 700 ms 判说完、段上限 30 s、起音回填 60 ms、不足 250 ms 的碎段丢弃；切出的每一段仍走 `asr.transcribe_file`，识别插件不感知流式。
- **部分结果**不等于引擎流式：说话中把已积累的整段音频重新识别一遍，推 `partial` 供界面实时展示。它只作展示，`segment` 才是定稿；同一时刻只跑一条，间隔随说话时长从 0.8 s 翻倍到 8 s，整段一切出在途结果即作废；当前引擎声明为云端时这一路整体关闭（每次部分结果都是一次整段计费）。这样不会把识别队列排在收尾段前面，也不要求任何一台引擎支持流式返回。
- **为什么不用 audio.cpp 的 `/v1/audio/transcriptions/live`**：那条原生流式入口可用，但当前默认的 `sense-asr` 是缓冲式实例——实测整段音频收完才回一条 delta（`ttft_ms` 等于整段时长），换过去反而没有“边说边出字”。接 cache-aware 流式模型（如 Nemotron、Voxtral realtime）时，可在 `usecase/asr_stream` 里加一条旁路，插件契约仍不必改。
- **流式依赖**：`silero-vad`（TorchScript 模型）与 `torch` 是可选项，缺失时端点回一句“请安装 silero-vad”而不是 traceback；VAD 模型按连接加载，推理在工作线程，识别另起协程按序听，收帧不被识别卡住。
- **能力**：文本恒有；语种检测可选。情感、声音事件、逐词时间轴不声明，界面如实列出「不支持」（SenseVoice 模型带事件/情感标签，但当前 HTTP 结果不返回）。
- **语言清单**：由各插件自行登记（Qwen3-ASR 30 种语言 + 22 种中文方言，SenseVoice 21 种），面板按清单渲染。
- **应用层选项**（`config.asr_options`）：自动识别、写回样例、录音自动转写、语种写回。开关仅在当前引擎声明对应能力时出现。
- **自动识别的前置**：所有自动识别（连接时补逐字稿、缺逐字稿时自动识别、录音后自动转写）先过 `usecase/asr.unavailable_reason()`——与设置页「引擎状态」同一判据；批量补全另加一次 `reachable()` 探测（与「测试连接」同一个调用），服务连不上就不起线程，只留一行日志。
- **连接时自动识别**（`auto_on_connect`，默认关）：识别服务可用时（启动、保存引擎设置、测试连接成功、切换引擎），后台把库里 `samples.text` 为空的样例逐条听一遍并写回，**一直补到没有为止**。每批 200 条、批间重新查库；写回后文字非空，不会重复识别。界面用 toast 显示进度，`POST /asr/fill/cancel` 可停（当前这条收尾，不再开始下一条）。
- **语种写回**：仅当该样例为主样例且音色语言为空时写入；已有值不覆盖，非主样例只回显。
- **输入约束**：识别接口只接受「音色 id + 文件名」，路径由服务端拼接。麦克风语音输入听完即删；参考音频录音存 `<数据目录>/recordings/`，服务重启清空。
- **浏览器录音**：麦克风音频在浏览器端解码、重采样为 16 kHz 单声道 WAV；转换时量峰值，整段低于 -60 dBFS（约 0.001）视为输入设备没有信号，不落盘、不上传，界面点名该设备并提示换输入设备。
- **内录**（`infra/loopback.py`、`usecase/capture.py`）：录默认输出设备上正在播放的声音，走 WASAPI loopback（`soundcard`），浏览器不参与。44.1/48 kHz 单声道 PCM16、边录边写盘、60 分钟自动收尾；全程静音不是失败，结果带 `peak` 与 `silent` 由调用方提示。产物落 `recordings/`，与参考音频同一套清空规则。起停只有两个入口：托盘菜单与全局热键（托盘 `RegisterHotKey`，组合键由 `usecase.capture.HOTKEY` 下发）；热键注册结果写回应用层，供设置页显示可用性。`start.bat` 无托盘时热键不注册，界面显示「托盘启动后可用」。

## 8. 对话模型

对话模型独立于 TTS 引擎：请求为消息数组，返回消息与用量。内置两家。

`deepseek`（云端）：

| 项 | 取值 |
|---|---|
| 模型 | `deepseek-flash`、`deepseek-v4-pro` |
| 上下文 | 1M |
| 思考 | `thinking` + `reasoning_effort`，可按请求覆盖 |
| 视觉 | Flash 支持内容块（图片/文件），Pro 仅文本 |
| JSON | `response_format: json_object`；字段级 Schema 降级并在 `notes` 中说明 |
| 错误 | 401 / 402 / 404 / 422 / 429 / 5xx 分别报出 |

`lmstudio`（本机）：OpenAI 兼容服务，默认 `http://127.0.0.1:1234/v1`；没有密钥也能用。

- 模型清单由本机服务返回；`model` 默认留空 = 用当前已加载的模型——请求前先查本机清单（`/api/v1/models`，旧版本 `/api/v0/models`，再回落 `/v1/models`），优先已加载的、跳过向量模型，也可填固定 id。
- API Token 只在本机开启「需要认证」时填；默认请求不带 `Authorization`。
- `response_format` 同时支持 `json_object` 与字段级 `json_schema`；工具按 OpenAI 形状透传。不提供联网搜索与思考力度。
- 采样参数只发填了的那几项：`top_p`、`top_k`、`repeat_penalty`、`presence_penalty`、`frequency_penalty`、`seed` 默认空着，空着就不进请求体——沿用 LM Studio 给该模型调好的那套，插件不拿自己的默认值覆盖它。上下文长度不在请求里：那是加载模型时定的，清单里逐条读出展示。

插件不支持的能力不硬发：降级与截断原因写入 `ChatResult.notes`，随响应返回。自检与模型清单的失败返回 `200 + ok:false`；补全失败返回 400。

## 9. 生产方插件

生产方拥有「书」的数据与处理流程，其他能力调用宿主：

- 项目、章节、行、角色映射、任务存插件自己的 SQLite；逐行音频与成品存项目目录。
- 分析调用 `usecase.llm`，合成调用 `usecase.gateway`，不直接持有密钥。
- 路由挂在 `/api/v1/producers/<key>`；前端按 `web/src/producers/<key>/` 懒加载工作区，宿主不出现插件名。
- 设置 → 插件是生产方唯一的入口：一张卡装一个插件（图标、名称、版本、启停状态、说明），卡上可直接打开工作区；声明了配置 schema 的插件在卡内展开「设置」，表单照 schema 画，画哪几组由插件的 `settings_page_groups` 声明。设置页不再为生产方单开分组。
- 启用 / 停用生产方：停用是服务端状态（`config.json` 的 `producers_disabled`），启动时不构造该插件的服务、不跑它的自动启动，接口一律拒绝；重启也不会自己起来。导航收起只是它的结果。项目、配置与成品都保留，随时可以再启用；启用时立刻构造服务，audio.cpp 开着自动启动就在这一刻拉起实例。
- 导航位置由插件声明：`order` 决定同组内的次序，`nav_section`（`main` / `tools`）决定落在日常页组还是下半段工具组。工具型工作区（运行时管理这类）声明 `tools`，与引擎、日志摆在一起，不占日常页的位。

- 宿主按 `ProducerPlugin.rail_mode` 摆左栏：`pick` = 点卡即选中、卡右「添加」把卡加入处理序列；`assign` = 卡右「指定」交给工作区。两种都对音色卡生效，宿主不认识具体插件。

当前内置 `audiobook`（导航名「创作」）与 `audiocpp`（导航名「audio.cpp」，属工具型工作区、不声明流水线步骤）：实例地址与模型 id 取自**引擎设置里的服务地址**（不另存端口表），且只列**模型已装在本机**的实例（引擎里配了地址不等于这里有服务；跑着的服务仍会列出，免得藏掉别人的进程）；用内置运行包或用户指定的 audio.cpp 程序拉起；运行包清单随插件分发，可显式同步上游最新 Release，同步结果落插件数据目录、可读时优先、坏了退回内置，最低要求始终取内置门槛，CUDA 包的 cudart 依赖与主包一并下载解压、界面按合计大小显示。装第一台模型时没有可点的实例，安装动作会先按引擎地址拉起一台空实例；模型清单取自上游 `model_specs`，安装/停止/删除转发实例自己的 `/v1/ui/models/*`。拉起的实例带 `ui` + `ui_management`（0.9.4 起 native model manager 编进运行时），所以实例行给「界面」入口，用户也能在它自带的 WebUI 里装模型；插件是一台实例一个模型、靠进程隔离，不用 audio.cpp 单进程多模型那套 LRU 卸载（`--max-loaded-models` / `--idle-unload-ms` / `--min-free-memory-mb`，默认全关）。实例行**没有**「接入」这个动作：那些端口本来就是引擎在用的地址，VoiceHub 合成时连的就是它们；服务在别处（换了机器或端口）时才用服务卡底部的「其他地址」做一次只读接入，断开即回到实例视图。数据模型、阶段、状态与失效规则见 [audiobook-flow.md](audiobook-flow.md)。

### 音色处理（voiceclean）

工具型工作区，左栏复用音色库（`voice_rail=true`、`rail_mode="pick"`），对象是样例行而不是项目。**序列由音色卡窗口组成**：点音色卡 = 打开这张卡自己的窗口（列出它的样例，不重置已有的移出与裁剪）；卡右「添加」= 把这张卡加进序列并打开它，第一次与以后再添加都得到全部样例，只补回被移出的行。多张卡时顶上排页签切换，每张卡的样例只在自己的窗口里，不混行；窗口按「音色 + 文件名」认行，同名样例落在不同音色上互不顶替。左栏的选中仍落在宿主的 `store.pick`（`voiceId` + `file`）：点卡打开、卡右「添加」加入序列、详情里的「使用」只加一条。文件夹树只用来筛左栏，不再是一种范围。平台音色没有本地文件，选它只提示，开始按钮保持禁用。

也可以从电脑选一份音频：顶部「选择文件」、空态的按钮，或把文件拖进工作区。文件上传后成为唯一目标，左栏选中随之清掉；在左栏重新点音色，文件目标让位。文件目标存在插件的 `fileTarget`（token、原名、时长），不上音色库、没有样例行以外的范围。

窗口里的样例表就是这张卡的处理序列：行首是播放键（试听原声），行尾焦点键把序列收成当前这张卡、X 把这一条移出；页签的 X 把整张卡移出序列。目标卡头像与左栏一样，悬停盖播放遮罩、点击按顺序播放这条音色的样例；页头标题右侧的播放键按页签与行序试听整个序列；清除目标是音色卡右上角的 X。点音频条主体，这一行自己展开成裁剪面板（再点收起；行尾不再单设裁剪键）：在波形上拖动框选，按「删除选区」连续删掉不要的区间，按「仅保留选区」把当前选区变成唯一保留段，撤销 / 前进回退每一步，恢复原样回到整段，最终至少保留 0.1 秒。结果不回写到界面的保留范围之外，替换后文件时长就是保留时长。裁剪在生成原声副本时一次完成（多段按序拼接），后续模型步骤与收尾只看保留的段；折叠行不画波形。处理后的结果不另开一张表：状态、时长与原声 / 处理 A/B 都回到同一条行上；「开始处理」在处理链卡片里，底栏只负责确认替换、入库或下载。

一条音频的执行顺序固定为「原声副本 → 勾选的模型步骤 → 可选的收尾（统一声道与峰值）」，模型步骤按处理常识排序、不随提交顺序变化：**人声分离 → 语音降噪 → 带宽扩展**。先分离，后面的降噪与扩频才只面对人声（先降噪会把伴奏当噪声削掉，分离也就没有依据）；先降噪再补高频，补出的高频后面不会再被降噪当噪声削掉。编排在插件里，ffmpeg 由核心提供（`infra/ffmpeg.normalize`），模型由本机 audio.cpp 的 `POST /v1/tasks/run` 提供（`task=sep|s2s`，`request.audio` 给服务端本机路径；响应里的音频按 `audio` / `result.audio` / `artifacts[]` 依次取，分离取人声那一路）。收尾不属于模型链：处理前只对齐单声道，高通与限峰放在所有模型步骤之后、原声与结果各做一次——模型吃原始电平，A/B 的差异只来自模型。步骤卡分「人声分离 / 语音降噪 / 带宽扩展」：前两张按 `task` 取白名单，语音降噪还能选内置小模型（DeepFilterNet2、RNNoise、ZipEnhancer、GTCRN），带宽扩展只收 FlashSR；内置工具没有 package，按模型 id / 路径认。带宽扩展是生成高频的轻量超分（FlashSR）：只用于本身窄带的素材，44.1 / 48 kHz 会先降到 16 kHz 再补，真高频反而丢了；它补出的高频不适合做训练素材。超分（AudioSR / UniverSR）不列进降噪，理由相同。每张卡列出该步登记的默认包与内置工具：未下载可在卡内下载，下载后自动登记/加载，不出现「已下载未加载」；只有一个可用模型时自动选中，多个时由用户选。内置工具权重由本插件按固定上游版本与 sha256 下载，加载走 `/v1/models/load` 的 `path` + `load_options.utility`；官方包走 audio.cpp 的安装/加载接口。服务地址取自正在运行的 audio.cpp 实例（`audiocpp` 的 `/v1/models`）；没有实例时自动拉起可管理实例，没有运行包时卡片写明去 audio.cpp 页安装。非默认精度的包只有已安装或正在运行时才列出。没有模型步骤时，只做裁剪也能生成结果；收尾默认不选，启用后做高通 60 Hz、限峰 −1 dBFS 并校验时长。单声道对齐与回库采样率不随这一档开关：处理前恒转单声道，回库恒按原样例采样率。回库结果按**原样例采样率**落盘（16 kHz 小工具或 44.1 kHz 分离不会把库里的 48 kHz 样例改低）；入库时模型输出比原样例高则保留原生采样率（带宽扩展补出的高频不被降回去）；文件目标保留模型原生输出。

两条产物（`origin.wav` / `result.wav`）留在任务目录，逐条 A/B 试听后写入库，确认之前不动库。确认有两个动作：**替换**与**入库**，替换需再点一次确认。替换走 `LibraryService.replace_sample_audio`：同目录临时文件 + `os.replace`，原件进回收站，文件名、逐字稿、主样例都保留，裁剪与处理链记进 sidecar 的 `samples[file].params`。入库走 `LibraryService.add_sample`：结果另存为「源基名（处理）.wav」（重名加序号），文字 / 情绪 / 标签从源样例带过来，原样例与主样例都不动，处理链同样记进 sidecar 的 `samples[file].params`；入库是新样例，只有替换受 50 ms 时长限制。A/B 与行首试听都走宿主播放器，不另起音轨。

时长偏差超过 50 ms（`service.DURATION_TOLERANCE`）的条目只拦替换——长度变了，贴齐、逐字稿与平台凭据全部错位；入库不受这条限制，带宽扩展或修复改变长度的结果也能留成新样例。

电脑文件没有可替换或可入库的样例：处理完只把 `result.wav` 交出来，按原文件名加「（处理）」下载；`job/apply` 与 `job/save` 对文件目标直接拒绝，也不做 50 ms 时长校验。上传的来源按 token 放在 `data/producers/voiceclean/sources/<token>/`，超过 24 小时自动清。

波形由前端解码（`web/src/composables/waveform.js`，`OfflineAudioContext` + RMS），按音频 URL 缓存；只画在展开的裁剪面板里，折叠行不画波形。解码失败时手柄仍可拖动，不影响裁剪。后端不算峰值。

接口在 `/api/v1/producers/voiceclean`：`state`（步骤、核心步骤与各步候选模型及下载/加载状态）、`models/download`（按 `{step, model}` 下载，完成后自动登记/加载）、`source`（multipart 上传电脑文件，上限 50 MB，容器限 WAV / FLAC / MP3 / M4A / AAC / OGG / OPUS）、`source/audio`（内联试听上传的原声）、`run`（目标 `{kind, token, voice_id, file, files, trims, voices}`：`kind=voice` 时按单条音色范围，`kind=file` 时只认 `token`，`kind=voices` 时按 `voices: [{voice_id, files, trims}]` 的组序拼接条目；`files` 是处理序列里的文件，`trims[file]` 是 `{segments: [{start, end}, ...]}`，兼容旧 `{start, end}` / `end=0` 表示到结尾；没有模型步骤与收尾时，至少要有一段非整段的裁剪）/ `job` / `job/cancel` / `job/clear`（清掉已完成的任务，回到可编辑状态）、`job/audio`（原声或结果）、`job/download`（文件结果按原名加「（处理）.wav」下载）、`job/apply`（按处理序列替换；文件目标拒绝）、`job/save`（按处理序列入库为新样例；文件目标拒绝）。任务单模型并发 1，逐条写 `running`，进度只数已完成的条，取消在条与条之间生效。

### 角色对话（realtime_chat）

工具型工作区（`voice_rail=true`、`rail_mode="create"`、`steps()` 为空）：和角色聊几句，回复按当前模型生成、再按角色音色合成。对话、合成与识别都复用宿主：`/llm/chat`、`/synthesize`、`/asr/stream`。本插件只存「和谁聊、长什么样、聊过什么」；对话模型挂在整份状态上，换角色不换模型。左栏音色卡右端是「创建」：点它就用这张卡新建一个角色，名字与介绍取自音色卡的名称与描述，声音沿用这张卡，并直接打开角色设置。

数据是一份 JSON（`data/producers/realtime_chat/state.json`），单进程单用户，坏文件留在旁边再回落默认。一个角色下挂多份记录：

```
{ version: 2, active_id, llm_provider, llm_model, characters: [{
    id, name, intro, persona, voice_id, voice_name, voice_engine, voice_engines,
    voice_cover, voice_local, voice_sample_mode, voice_sample_file, background, portrait,
    portrait_x, portrait_y, portrait_scale,
    sessions: [{ id, created, messages: [{ id, role, text, audio_url, created, error?, audio_error?, notes? }] }],
    active_session }] }
```

- `intro` 是名牌上那一句（给人看的），`persona` 是给模型的指令，两处分开：名牌不显示系统提示词。都没写时名牌说「还没有写下她是谁」，不编一句。
- 记录的标题不存库：取这一份里「你说的第一句」，没有就按日期说。日期说法（今天 / 昨天 / 几月几日）只在前端派生。
- 版本 1 的状态只有 `messages`：读进来收成一份记录，聊到一半的内容不丢。规范化时记录最多留 30 份、每份最多 60 条；`active_session` 指向不存在的记录时落到最新一份。
- 对话模型在顶层（`llm_provider` / `llm_model`）：换角色不该换模型。旧状态把它写在角色里，读进来时把第一处非空值搬上来；角色只留「和谁聊、长什么样、聊过什么」。
- `voice_engine` 默认 `auto`：每次合成从 `voice_engines` 里挑一台**此刻有绿点（实例真在跑）的本地引擎**；没有就那一句写「没有可用的合成引擎」，不拿没起的实例顶上去。云端引擎按量计费，本页不列、也不自动选；这条音色只有云端时明确说没有可用的本地引擎。
- `voice_local` 标记这条音色是不是库里的本地音色；本地音色才有 `voice_sample_mode` / `voice_sample_file`（与创作页同一套样例策略）：`emotion` 按情绪匹配（聊天没有逐句情绪，认不出就回落主样例），`fixed` 钉住某一条样例。这两项随 `/synthesize` 的 `sample_file` / `match_emotion` 透传给网关；平台音色不带。`fixed` 却没有文件时规范化回落 `emotion`，不留一个永远失效的档位。

界面是一间「房间」而不是一叠卡片：房间 = **背景** + 可选的**立绘**。背景有随包分发的四张——书房 / 雨夜 / 晨光 / 霓虹（第一张是默认），也可以换成用户自己传的一张；立绘是十一张各家模型的拟人图（透明底 WebP，见 `web/src/producers/realtime_chat/assets/CREDITS.md`，来源是自备素材，非本仓库原创；其中 Claude 的 Q 版与 GLM 的轮椅版是同一画手的备选稿），站在左下角，脚贴地面、投一层影，右半的台本压在她之上。没有「没设图就一块纯黑」那一档：旧版本留下的 `builtin:scene` / `builtin:code` / `mist` 等键已经没有素材，读进来落到默认那张。

立绘不是必选项（`portrait` 为空就是只留房间），但每张立绘都配了一张默认背景，选人时连房间一起换；窄档（房间 ≤900）没有两栏，立绘整张收起，只留房间。立绘可以在画面上直接拖动换位置、滚轮调大小，位置与大小按角色保存（`portrait_x` / `portrait_y` / `portrait_scale`），角色设置里有「复位」。晨光那张整体偏亮，`.is-bg-dawn .rc-shade` 单独加深右半，白字才压得住。

名牌排在**左上角**，底下垫一层从左上散开的暗雾；角色切换的名单向下展开。立绘仍站在左下、脚贴地面，但离左沿留一点距离，不贴着画框。台本是一条贴右的窄带（约四分之一宽），磨砂与暗化只负责可读性；可以整块收起，只留右边一枚无边框的「<」。

房间按**自己的宽度**排版，不按视口：这一页夹在导航、分类栏与音色列之后，视口 1440 时屋里可能只有 900 出头。断点走 `@container room`——两栏不够时名牌回到台本上方、台本自己压一层向下的暗化；够宽时恢复左右构图。台本列按百分比取宽（24%–28%，宽档封到 640 / 700），**收掉左侧音色栏后台本顺势变宽**，不留一截空画面。

- 名牌：名字、`intro`、「编辑角色」与音色胶囊；角色不止一个时下方排一行名字用于切换（`+` 新建，最多 12 个），**在名牌上滚轮也能直接翻人**（一次滚动换一个，触控板惯性不连翻）。音色胶囊在回复出声时换成三根呼吸的条子。
- 台本：换人时才写名字，连着的几句只写一次；你说的那句缩进、字号小一档、名字写「你」；出错的那行名字写「出错」，正文只说原因。句尾挂播放（已合成）或合成（还没有音频）的小按钮，没有音频时另有一枚「这一句没有语音」的标签，原因在 `title` 里。她念出来的那一句会以半透明雾面气泡出现在立绘旁，播放结束就散——窄条只做记录，不必盯着读。
- 输入：无边框，回车发送、Shift+Enter 换行；下方是听写开关、对话模型胶囊与「Enter 发送」。模型胶囊就在输入框旁边，点开才露出服务与模型两栏——选模型不用翻角色设置。连续听写时，识别中的话以一行「你 · 正在说」实时出现在台本末尾。
- 角色设置从名牌处就地铺开（不是弹窗、不换页）：名字 / 介绍 / 人设（旁边一颗「AI 生成」，按名字与介绍让对话模型写）/ 声音（合成引擎收成一行下拉、左边绿点表示此刻真有实例在跑；本地音色的样例策略与样例下拉、试听）/ 立绘（十一张 + 「不站人」）/ 背景（四张内置图 + 上传自己的一张），底部是「删除角色」；Esc 或点画面收起。用音色卡新建时这张纸标题写「新建角色」，介绍已由音色描述填好；人设留给「AI 生成」按名字与介绍现写，创建时不偷偷花一次模型调用。
- 记录抽屉压在台本这一层上（`目录` 或 `记录 n` 打开）：按时间倒序列出每一份，行内删除要就地再确认一次；底部「新的一份记录」。只剩一份时删除等于换上空白页，列表永远有东西可点。

记录、播放条与试听共用宿主的播放器：`playMessage` 只是把这条的 `audio_url` 交给 `playAll`（`sub='回复'`），台本上的「正在念这一句」由 `player.url` 反查得到，停止或换曲时自己熄掉。合成走 `persist: 'none'`，字节回落到插件自己的 `audio/` 目录，消息上只记那份地址；识别说完一段自动发送，上一轮还在忙时落回输入框并提示。

接口在 `/api/v1/producers/realtime_chat`：`state`（GET / PUT 整份，PUT 由前端唯一写方，规范化后落盘并回同一份）、`backgrounds`（multipart 上传，PNG / JPG / WebP，上限 8 MB）、`backgrounds/{name}`（读图，文件名带随机串可长缓存）。

## 10. API

### 约定

- 前缀 `/api/v1`，无别名。
- 集合响应：`{"object": "list", "data": [...], "has_more": false}`；单资源带 `object`；删除返回 `{"id", "object", "deleted": true}`。
- 分页：`limit` / `offset`，默认 `limit=0` 表示不分页；`limit>0` 时 `has_more` 由多取一条判定。
- 压缩：非回环来源启用 gzip（正文 ≥ 1 KB），本机请求不压缩。
- 错误体：`{"error": {"message", "type", "code", "param", "request_id"}, "detail"}`；`type` 为 `invalid_request_error` / `not_found_error` / `engine_error` / `internal_error`。响应带 `X-Request-Id`。

## 11. 前端

### 布局

主区同时只有一个视图：音色库、生成页、音频库、引擎面板、生产方工作区、日志、设置。左栏负责切换与范围选择。

左栏不另设收起控件：再点一次当前页的导航图标（内置页与插件页的图标都一样），在「目录树 + 音色栏 → 只有音色栏 → 都收起」三档间循环；没有音色栏的页只在「有目录树 / 无目录树」两档间切换。图标提示写出下一档（收起目录树 / 收起音色栏 / 展开左栏）。主区随可见列拿回宽度；收起只隐藏、不卸载，卡片列表与冻结参考都留在原处。档位记在本机外观偏好里，换页与刷新后保持；窄屏本来就把第二列与卡片列收回或改成横排，收起只是把这几列让出来。

主导航分上下两组：上半是日常页，依次为音色库、生成、各生产方工作区（按插件 `order`）、音频库；下半是工具，依次为声明 `nav_section='tools'` 的生产方、引擎、日志；设置单独一档。按「素材 → 动作 → 成品 → 工具」排：音色库是素材，音频库是成品，工具型工作区与引擎都在下半段。

- 音色库：左栏为「全部音色 / 各引擎音色层 / 设计音色 / 扫描根分类 / 引擎」。设计音色是一条跨引擎的来源，形态与目录条目一致（点一下只看这一组），标识另设：一枚圆角小牌里放 ✦，与引擎的方形图标、扫描根的线框文件夹相区分；`?source=` 的查询**排除**设计音色（它们只归自己那一组，也不计入任何引擎的条数），「全部音色」的总数则是本地 + 各引擎 + 设计音色三部分之和。左栏选中在每一页都标出来（淡底 + 左沿一道实色 + 字色转强调），生成页也标——那一列音色卡筛的就是这一组。音色卡只报样例数，不再挂引擎名（来源由左栏分组与详情头回答）。主区为筛选栏与卡片网格；右侧为详情抽屉（增删都在这边：设计音色的「移除」是详情右上角那颗垃圾桶，生成页不摆删除）。标签条在条首有一颗「标签」开关：标签多时收成一行，收起后仍写出当前筛的标签，再点展开；状态存本机外观偏好。
- 生成页：左列音色卡，列头是一条「参考音频」功能条（录音 / 顺序播放 / 使用设计音色）；点卡即选中，并用它自己的主样例作参考音频（卡片右端的「选样例」才开详情挑别的一条）。列头录的那一段可以单独当音色：不选库内音色也能生成，录音不在库里、只活在临时目录。中间写正文、标情绪、勾引擎，右列调参数。参考音频不单占一段：选中的音色连同那条样例置顶冻结在左列头上，卡片列的播放键放的就是这段参考。冻结卡与普通卡同一副长相（头像、名字、性别、设计标签、样例数都一样，末端多一颗「换样例」），另盖一枚斜置的朱砂「参考」印（绝对定位、不占行高；朱文单线、隶书，框贴着字走，两处缺墨由 SVG 蒙版真挖空）。印章**不看有没有样例**：它表示的是「这次用这条音色配音」，设计音色与临时录音同样盖。置顶的强调取印章的朱砂（一层淡底 + 左沿一道），不取强调色——强调色是列表里「选中」的语法，同一个音色在下面也亮着，同色就得猜哪一处才算数。悬停与选中的强调一律走底色与字色，不走边框——这一列已贴成一整块面板，行间那条细线是结构线。列表按整张卡翻：卡高由可视高均分（`--rail-card-h`），停手时由 `scroll-snap-type: y mandatory` 把落点对到卡边，因此不会停在半张卡中间；`scroll-snap-stop` 不设成 `always`，否则一个手势只走一张，长列表翻不动。
- 生产方工作区：左列音色卡片；中间是步骤条与正文；右列是章节目录。音色管理与合并收在行表上方最右侧的一颗按钮里，分配表在弹窗里改，界面由插件自己摆。平板（≤1400px）把右列目录改成表格上方的横向条，行表拿回整幅宽度；≤1100px 再收紧列距与固定列，并收起音色卡片列（挑音色仍从「音色管理」进）。行表不再锁固定最小宽度，正文列随容器收缩，五行一起留在视口里。
- 引擎面板：主区页面而非弹窗，页签与表单由插件声明。
- 筛选条件（搜索、性别、年龄感、语言、标签、显示已隐藏）存入 `localStorage`，恢复发生在首次拉列表之前。

### 大列表

音色库可能有数千条。列表按三层减速，缺一层都会在主线程上看出来：

- 卡片分帧挂载：首屏 48 张，之后每帧补 48 张，加载期间界面仍可滚动、可点。
- 屏外卡片 `content-visibility: auto`，跳过排版与绘制；`contain-intrinsic-size` 按默认密度估算，渲染过的行记住真实高度。
- 封面统一走 `/cover/{id}?s=thumb`：首次请求把原图缩成 160px WebP 缓存进 `<缓存目录>/covers/`。头像原图 0.5–1MB，缩略图约 8KB；原图地址只留给"换头像 / 看大图"。
- 卡片上的性别控件只在点开时挂浮层（`v-if`），几百张卡不常驻 Teleport 与全局监听。

### 主题

设计令牌定义在 `web/src/settings/theme.css` 的 `:root`，深色覆盖 `[data-theme='dark']`，组件只引用变量。

外观分五套（`data-look`），默认原色：

| 值 | 名称 | 特征 |
|---|---|---|
| `classic` | 原色 | 冷灰底、白色面板、冰蓝强调、小圆角；全部表面为实色，无渐变、内高光、模糊与发光投影 |
| `paper` | 纸墨 | 米纸底、墨色字、朱砂强调、衬线标题、小圆角、无模糊 |
| `celadon` | 素瓷 | 冷白瓷面、青釉强调、大圆角、柔和阴影、无模糊 |
| `glass` | 玻璃 | 半透明面板、背景光、`backdrop-filter`、可调模糊与圆角 |
| `stage` | 舞台 | 设计稿那一套：暖灯强调色、衬线名字、顶栏与左栏压在画面上的半透明带；日场是暖纸墨字，夜场是设计稿那间暗屋，两场各一套完整令牌 |

外观的令牌落在 `:root[data-look=…]` 上（日场）与 `:root[data-look=…][data-theme='dark']`（夜场），壳外（弹层、Toast、原生控件、媒体面）才拿得到同一份颜色；只挂 `.app-shell` 会得到半浅半深的一张脸。每套外观都要把 `theme.css` 的 `:root` 令牌覆盖完整，缺一个 `--sh-field` 就会在深底上冒出白输入框。

外观只换材质，不改结构尺寸：`--sh-nav-w` / `--sh-rail-w` / `--sh-gutter` 归 `theme.css` 的响应式，外观文件里写死会压过断点，窄屏不收。

非玻璃外观还要在各自的 `look-*.css` 里按选择器压掉组件写死的渐变、内高光与毛玻璃——只换令牌压不住 `linear-gradient` 与 `backdrop-filter`。

主题模式（浅色 / 深色 / 跟随系统）由 `store/shell.js` 写入 `<html data-theme>`，首屏内联脚本在绘制前恢复，避免闪烁。

无封面头像是按名字散出的稳定底色：玻璃与素瓷用双色渐变，原色与纸墨用平涂；选择统一走 `composables/avatarColor.js::avatarFill(name, look)`，音色库卡片、左栏、详情头与处理页目标共用这一处。音色栏的卡片式选中（外边距、圆角、整卡抬起）同样只属于玻璃与素瓷；原色与纸墨保持整列贴面板，选中只换底与左沿。

外观主题里还可以收起主导航：`data-nav-auto` 让导航不占列宽、鼠标移到左边缘或键盘聚焦时滑出；`data-nav-labels` 只留图标。两项都只作用于桌面，窄屏导航横排在顶部。头像的显示与「头像匹配」（来源顺序、候选、裁切）同在外观主题，不再单开一组。

### 界面规范

以下规则适用于所有页面与生产方工作区。

#### 令牌

- 颜色、圆角、间距、阴影、透明度、动效的值写在 `web/src/settings/theme.css` 的 `:root`；深色覆盖 `:root[data-theme='dark']`。
- 组件只引用 `--sh-*` 变量，不写十六进制色值，也不写 `var(--x, #hex)` 兜底。例外只有主题/外观层（`theme.css`、`look-*.css`）与插件图标 SVG 数据。
- 旧变量名（`--bg` / `--panel` / `--accent` / `--radius`）在 `web/src/style.css` 中作为 `--sh-*` 的别名，不复制色值。
- 圆角与间距使用阶梯变量：`--sh-r-*`、`--sh-radius-card`、`--sh-gap-1…6`。
- 强调色与密度是用户偏好，挂在 `.app-shell` 上覆盖；基础令牌在 `:root`。
- 风格层（`look-*.css`）只覆盖令牌与必要的硬编码形状，选择器统一带 `:root[data-look='<key>'] .app-shell` 前缀。

#### 组件

- 公共控件位于 `web/src/components/ui/`：`ActionButton`、`TextField`、`ToggleSwitch`、`RangeSlider`、`SegmentedControl`、`ChipToggle`、`PanelCard`、`SchemaFields`、`ChipSelect`、`TagChips`、`Popover`、`ContextMenu`、`GenderPicker`、`MicButton`。
- 设置页组合件（`SettingCard` / `SettingRow` / `SettingsSection`）位于 `settings/ui/`。
- 优先使用公共控件。使用原生控件时：输入与下拉挂 `.sh-field`，按钮挂 `.sh-btn`（`is-primary` / `is-ghost` / `is-soft` / `is-icon`），不新增第三套类名。
- 右键菜单只有一份：`ui/ContextMenu.vue` 负责渲染、定位与键盘，`menus/catalog.js` 按对象类型给菜单项；对象的右键与行尾「⋯」共用同一份定义。宿主目录只留通用对象（音色卡、样例、日志、引擎等），生产方专属对象由插件 `index.js` 引入自己的 `menu.js`、调用 `registerMenus()` 注册，宿主不写具体插件名。输入框、下拉、可编辑区、非折叠文本选区与 Shift+右键保留浏览器菜单；创作页的行文本输入标了 `data-app-menu`，没有选区时右键交给行菜单（带选区仍走浏览器菜单，复制粘贴不丢）。
- 设置项按后端 `ui_hints(group=...)` 分组；依赖项置灰并说明条件。
- 插件设置表单（引擎 / 对话模型）使用平面表单，不套卡片；设置页仍使用 `SettingCard`。
- 插件设置与设置页共用 `SchemaFields` 行表：分组、行、控件列宽由宿主提供，插件只交 schema。
- 焦点态只有一层：控件自绘边框与 ring，并设置 `outline: none`；全局 `:focus-visible` 只用 `:where()` 兜底。

#### 图标

- 只使用 `lucide-vue-next`，不混用字符图标。
- 尺寸只用 12 / 14 / 16 / 18 / 20 / 24；描边统一 1.8。
- 图标按钮必须带 `title` 与 `aria-label`；默认色 `--sh-text-3`，悬停或选中为 `--sh-accent`。

#### 版式

- 页面 = 标题行 + 卡片栈；卡片间距由容器 `gap` 统一。
- 数据表页（创作）不叠卡：表头、工具条、表格依次铺在平面上，用分隔线分层。
- 应用页（引擎 / 日志）限制在 `--sh-page-max` 内居中；卡片墙铺满，通过网格增加列数。
- 工具型工作区的页头、正文、底栏共用同一条内容列：各自 `max-width: var(--sh-page-max)` 居中，横向内边距取 `var(--sh-gutter)`。只收窄正文会让标题与底栏留在面板两端。
- 行内动作分两层：主操作紧邻状态（未生成 = 生成、已生成 = 播放、失败 = 重试）；低频操作收进行尾「⋯」菜单。
- 同一动作只给一个入口；底栏常驻按钮放在 `panel-foot`。
- 播放条是嵌在顶栏中缝里的 46px「涨潮块」、右沿贴住居中搜索框（留 12px），只在有东西可播时出现：圆角面板 + 1px 边框 + 轻表面，底色本身就是进度——从左侧涨到当前时间，前沿一道水线，没有第二条进度线，因此不会压在顶栏下框线或纸墨装饰线上。左侧是音色名与样例位置（名在上、数量在下），中间三颗主按钮，右侧收藏 / 指定 / 开卡与收条；标题用音频文件名（音色卡试听用音色名），不写逐字稿。头像播放键排这一条音色自己的样例队列（从主样例开始），只供手动切上/下一条，播完当前这条不自动续播；「全部播放 / 全部试听」才自动续播。宽屏下它不改变搜索框的位置；宽度不足时收起「收藏 / 指定」（1440 以下），名字与数量仍在，1260 以下顶栏没有中缝，播放条回到行内排、搜索框随之让宽。搜索框不在这一页时退回音色栏上方。
- 键盘可达：可点元素使用 `<button>` 或带 `role` 的元素；焦点环由控件自绘，全局规则只兜底。
- 只有一个壳 `AppChrome`：设置页是壳内一屏，不要再给页面套第二层壳；弹层只走 `<Teleport :to="overlayTarget">`（`web/src/composables/overlayTarget.js`）。
- 生产方工作区由插件自描述：`voice_rail=false` 的工具型工作区同时隐藏左栏音色卡片、音色结构树与音色搜索；导航落点由 `nav_section`（`main` / `tools`）声明，宿主不按插件 key 判断。
- 长操作（扫描、补全、批量合成、合并）必须立即显示状态与进度，不能只留完成日志。短设置直接展开；多预设用下拉切换 + 保存/添加，不铺平列表或另开编辑弹窗。

#### 并发

- 合成并发取 `min(设置并发, 插件声明的 max_concurrency)`；引擎自己配了并发额度时按它的额度，不受项目设置盖住。
- 多引擎同批另有一把总闸：`max(设置并发, 最大单引擎额度)`，避免总并发按引擎数翻倍。
- 本机单模型服务（audio.cpp 的 GGUF 实例）必须声明 `max_concurrency = 1`；并发只会增加排队时间。
- 云端引擎不声明上限时，按用户设置执行。
- 云端平台的配额是 **RPM**，不是并发数：一条短句几百毫秒就返回，并发再低也能把每分钟请求数打穿。平台有每分钟配额的云端插件必须给出 `rpm` 设置项，请求一律经 `app/engines/ratelimit.py` 的闸口（并发位 + 滑动窗口）；平台没有该限制的在插件说明里写清。平台回限流时按错误码 `rate_limited` 冷却整台引擎并退避重试，不逐行判死。

### 状态与验证

`web/src/store/` 按域拆分（library / engine / synth / asr / shell），各域导出的函数合并为统一 `actions`；播放器为全局单实例。播放条与样例队列的行为见「版式」一节。

验证手段：

| 脚本 | 内容 |
|---|---|
| `pytest` | 后端单元与接口测试 |
| `scripts/smoke.py` | 接口冒烟，逐条报告失败 |
| `scripts/shot.mjs` | 无头浏览器界面自检与截图，校验服务端当前产物、页签与表单渲染、主题对比度等 |
| `scripts/make_demo.py` | 生成演示音色库，覆盖分类、多样例、单样例与平台音色 |

## 12. 运行与数据

| 项 | 规则 |
|---|---|
| 端口 | 默认 `17865`；`--port` > `VOICEHUB_PORT` > `config.json` |
| 监听 | 默认 `127.0.0.1`；`--host` > `VOICEHUB_HOST` > `config.json` |
| https | 默认 `auto`：监听非回环即开（自签证书落数据目录 `certs/`）；`--https` / `--no-https` > `VOICEHUB_HTTPS` > `config.json` 的 `https` |
| 数据目录 | 启动脚本默认设为 `./data`；可用 `VOICEHUB_DATA_DIR` 指定。未设环境变量而直接调用库时回落到 `%LOCALAPPDATA%\voicehub` |
| 单实例 | 同一数据目录只允许一个服务进程（`data/service.lock`）；第二个实例直接退出 |
| 配置写入 | 整份原子替换（`atomic.write_json`）；并发保存与坏文件回落仍未加固 |
| 生成目录 | 全局 `output_dir`，每台引擎可用 `engine_outputs[key]` 覆盖 |
| 缓存 / 日志 | `cache_dir` / `log_dir`，空则位于数据目录下 |
| 时长探测 | 优先使用配置的 ffprobe，其次随包 ffmpeg，最后 PATH；全格式合并与混音依赖 ffmpeg |

服务为单机个人工具：不提供用户体系；开放局域网时建议配置访问令牌，并在前面加一层带鉴权的反向代理。
