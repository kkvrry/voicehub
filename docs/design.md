# VoiceHub 技术设计

> VoiceHub 是单机运行的服务：管理音色库，向多台 TTS 引擎转发合成请求，并以「生产方插件」的形式提供有声书生产。
> 本文描述当前实现的结构与契约。请求参数的完整定义见 [request-spec.md](request-spec.md)，引擎接入契约与步骤见 [engine-integration.md](engine-integration.md)，有声书流水线见 [audiobook-flow.md](audiobook-flow.md)，界面与代码约束见 [AGENTS.md](../AGENTS.md)。

## 1. 范围

**提供**：本地与平台音色的统一管理、样例试听与编辑、多引擎合成中转、语音识别、有声书生产（分章 → 拆句 → 分析 → 逐行合成 → 合并）。

**不提供**：TTS / ASR 模型服务本体、模型权重下载、多用户与权限体系、云同步。云端引擎由用户提供密钥，本机引擎由用户自行启动推理服务。

## 2. 总体架构

```
浏览器（Vue 3 SPA）
    │  /api/v1
FastAPI（单进程）
    ├─ api/          HTTP 层：校验、序列化、鉴权
    ├─ usecase/      用例：音色库、引擎、合成网关、识别、对话模型、生产方
    ├─ domain/       模型与纯规则（零 IO）
    ├─ infra/        文件系统、SQLite、sidecar、配置、ffmpeg、日志
    ├─ engines/      TTS 与 ASR 插件（builtin/<key>/）
    ├─ llm/          对话模型插件（builtin/<key>/）
    ├─ embedding/    语义召回插件（builtin/<key>/）
    └─ producers/    生产方插件（builtin/audiobook/、audiocpp/）
```

- 后端同时托管前端构建产物，启动一个进程即可使用。
- 分层依赖单向：`api → usecase → domain / infra`；插件只依赖各自域的基类。
- 数据库为 SQLite：`hub.db` 存音色索引与配置状态；每个生产方另有自己的项目库。

### 目录

| 路径 | 内容 |
|---|---|
| `app/` | 后端（FastAPI） |
| `app/engines/builtin/` | TTS 与 ASR 插件，一台一个目录 |
| `app/llm/builtin/` | 对话模型插件 |
| `app/producers/builtin/` | 生产方插件，目前为 `audiobook`、`audiocpp` |
| `web/` | Vue 3 + TypeScript + Vite 前端 |
| `data/` | 运行数据：`config.json`、`hub.db`、项目库、缓存、录音、日志 |
| `docs/` | 设计、请求规范、流水线文档 |
| `tests/` | pytest |

## 3. 音色模型

### 3.1 扫描规则

用户可配置多个扫描根。规则由 `domain/scanner.py` 唯一实现：

1. 递归遍历；某一层**直接包含音频文件**（`.wav` / `.mp3` / `.flac` / `.m4a` / `.ogg`）的文件夹即为一条音色，文件夹名即音色名，不再深入子目录。
2. 该文件夹的上一级为分类；上一级是扫描根时分类为空。
3. 扫描根下平铺的音频文件各为一条音色，音色名为文件名去后缀。
4. 音色身份 = 文件夹绝对路径的散列。不同根下的同名音色是两条独立条目。
5. 扫描只读：不创建、不修改任何文件。`voice.json` 只在**编辑元信息**与**音频落盘**（`infra/archive.record_sample`）时写，扫描不碰。

### 3.2 增量扫描

`infra/walker.py` 在一次 `os.scandir` 中取得文件名、大小与 `mtime_ns`，生成目录指纹存入 `voices.scan_stamp`。下次扫描指纹未变时整条复用索引，不读 sidecar、不重建模型、不写库。音频时长另有 `probe_cache`（路径 + 大小 + mtime → 秒）。时长为 `0.0` 的记录不复用，以便后续重试。

`voice.json` 的每条样例还带一份时长备份 `duration` + `bytes`（写它的那个文件的字节数）。扫描先用 `probe_cache`；没命中时若字节数对得上（或缓存整体为空、老 sidecar 又没记字节数）就直接采用备份，不再起 ffprobe——改名、搬家、库重建时尤其值；字节数对不上说明音频换过，照常量真的。备份在**落盘那一刻**写（`archive.record_sample`），改样例文字时原样带着走。

### 3.3 样例文本

优先级从高到低：

1. `voice.json` 中用户编辑过的 `text`；
2. 与音频同名的 `.txt`（`开心.wav` ↔ `开心.txt`）；
3. 文件夹内 `list.txt`（每行 `音频名|文本`）。

界面编辑只写入 `voice.json`，不改训练用 `.txt`。说话内容同时作为参考文本随样例音频发给引擎，是一等字段。

### 3.4 存储分工

| 数据 | 位置 |
|---|---|
| 本地音色元数据、每条样例的文本/情绪/标签/时长备份、主样例 | 音色文件夹内 `voice.json` |
| 收藏/隐藏 | 正本在 `voice.json`（跟着文件夹走），`hub.db` 存副本并把侧边栏的筛选跑在库里 |
| 扫描根、平台音色条目、引擎配置 | 服务数据目录（`config.json`、`hub.db`） |
| 查询索引 | `hub.db`，可由扫描重建 |

`voice.json` 只写用户改过的字段，全部可缺省；`samples` 按键增量合并。写入采用临时文件 + rename，先写 sidecar 再更新索引；sidecar 写失败则接口失败。

### 3.5 数据模型

| 字段 | 说明 |
|---|---|
| `id` | 本地音色：路径散列；平台音色：`<engine>:<voice_id>` |
| `source` | `local` 或平台 key |
| `name` / `display` | 名称；显示名回落规则为 `display or name` |
| `category` | 分类：本地为上级文件夹名，平台为平台分类 |
| `gender` / `age` / `language` | 性别、年龄感、语言（BCP-47 主语言子标签） |
| `tags` | 多值特点词 |
| `folder` / `cover` | 本地音色文件夹与封面文件名 |
| `origin_id` | 该文件夹归属的平台音色 id（从 sidecar 的 `origin` 读入） |
| `samples` | 详情接口返回：文件名、文本、情绪、标签、时长、是否主样例 |

性别、年龄感、语言的候选词表只在后端定义，随 `/api/v1/tree` 下发；角色卡的两组固定标签（`语调` / `音色`）也随 `/api/v1/tree` 下发，选中的与自填词一样落进 `tags`——筛选、AI 匹配、配色不必另认一套。情绪候选来自生效词表（`/api/v1/vocab`，带 `groups` 分组），创作页总览同样带上分组。前端不保存第二份。候选不是白名单：词表外的值原样保留并显示。设置页「词表」只记用户差别（删除 `hidden` / 默认条目改名 `renamed` / 自定义 `custom`）；删除只改候选表，不动项目行上已经写下的标签。AI 辅助提示词（对话分析预设、匹配音色、角色画像、文本转正则）也由后端存默认与覆盖，设置页编辑，各任务运行时读同一份生效值。

主样例判定顺序：`voice.json` 的 `main_sample` → 文件名含「默认 / default / 主」→ 文件名升序第一条。`默认` 等词不计为情绪。

## 4. 插件体系

四类插件域共用同一套宿主规则：一个目录一个插件、自声明配置模型、配置存服务端、机密读取时掩码、自带图标与路由。

| 域 | 基类 | 发现 | 职责 |
|---|---|---|---|
| TTS 引擎 | `engines/base.py` | `builtin/<key>/` + `voicehub.engines` | 文本 → 音频 |
| 语音识别 | `engines/asr_base.py` | `builtin/<key>/` + `voicehub.asr` | 音频 → 文本 |
| 对话模型 | `llm/base.py` | `builtin/<key>/` + `voicehub.llm` | 消息 → 消息 |
| 生产方 | `producers/base.py` | `builtin/<key>/` + `voicehub.producers` | 源文本 → 章节 → 音频 → 成品 |

向量模型（`app/embedding/`）是独立能力：发现组为 `voicehub.embeddings`，不共用上表的配置存取与机密掩码，不计入四类插件域（发现机制仍与其他域同一套）。

- **发现机制**：以上五处的「怎么找」只有一份实现——`app/infra/plugin_registry.py`。各域注册表只声明基类、内置包位置与插件文件（写在子包 `__init__` 还是 `plugin.py`），不再各写一遍扫描与缓存。
- **发现顺序**：entry points 优先于内置目录，第三方包可覆盖同名内置插件。插件导入或构造失败时跳过并记一条 warning，不影响其他插件。
- **配置**：`settings_schema()` 返回 pydantic 模型，前端按 `model_json_schema()` 渲染表单。`""` 表示不修改；`{"_clear": [...]}` 清除机密；`{"_reset": true}` 恢复插件默认（机密保留）。
- **前端不识别厂商**：字段名、控件类型、候选值、能力说明、页签、参数映射均由后端下发。前端代码中不出现引擎 key 分支。
- **依赖方向**：插件依赖宿主契约；宿主不认识任何具体插件。删除插件目录即删除对应功能。

## 5. TTS 引擎

### 5.0 启用与停用

**发现一台插件不等于它在用**。发现到的引擎全部留在适配清单里（`GET /engines/catalog`），而左栏、生成页勾选、生产方候选、`engines_for_voice` 与合成网关只认**已启用**的那几台（`GET /engines`）。启用清单是 `config.json` 的 `engines_enabled`；缺这个键（升级前的配置）时按"用过的"推导：有配置段、有通道、有保存目录、是当前识别引擎，都算用过。推导结果不落盘，用户第一次启停时才写成明确清单。

界面上只有**一个控件语言：开关**。清单里每台一行、右端一个开关，开 = 启用、关 = 停用；引擎面板抬头同一颗开关显示当前状态，关掉即离开这一页（换到下一台已启用的）。没有"添加 / 删除"两套动作——那是同一个开关的两态。

各出口也只有一个字段：``enabled``（``True`` = 在用）。适配清单、引擎自描述、左栏树行都带它，极性一致；不要再另出一套 ``disabled``，两个字段并存迟早会有一处读反。

- 保存设置顺手启用（填了配置就等于在用），省一次"先开关、再配置"的往返。
- 停用不动配置，也不动库内音色：配置留着，音色在左栏单列一段「已停用的引擎」，点一下只看它们。删配置是另一件事，不在停用里做。
- 停用的引擎不能被调用：网关回 `engine_not_enabled`（400），不是 `engine_not_found`——前者一步就能解决。
- **口味与词表按已启用收束，引导指令预设例外**：语气词「通用」只在已启用那几台之间求交集；分配弹窗的引擎候选、健康检查的引擎状态、文本阶段的标签渲染，都只认已启用。引导指令预设是自由文本的"现成说法"，按**全部已发现**引擎的 `instructions.json` 合并，与启停无关——停一台不该让候选凭空少一段，发给不认这一格的引擎也只是装配时被剔掉。
- **生产方在计划期就收**：音色指向的引擎被停用时，这些行在生成计划里摘掉、按引擎记一条「N 行所属引擎已停用，已跳过」；不留在队列里逐行撞网关——那会变成一万行失败配一个原因。停用因此不损坏项目：重新启用后同一批行照旧能排进计划。
- **运行期同样只停不停说**：计划算完到跑完之间开关仍可能被关，批内第一行撞上 `engine_not_enabled` 就停掉这台引擎的剩余行，与「连不上」同一处置（`CODES_ENGINE_UNAVAILABLE`）：剩余行不发请求、不写行错误，留在待生成，日志与任务说明各一条。
- 库与归档仍按**全部**插件看：`engine_roots()` 要把停用引擎的保存目录继续从扫描根里摘掉，`generated_sample_path()` 也要找得到停用引擎留下的产物——停用不该让已有文件"消失"。同理，行参数面板按**插件身份**取引擎（回答"它能调什么"），不看启停：停用之后那些行仍要看得见自己的参数面。
- 识别引擎不在这套清单里：识别的"当前那台"由 `config.asr_engine` 单独回答。

### 5.1 能力与形态

`Capabilities` 声明：部署形态（`cloud` / `local`）、音色清单、音色克隆、音色设计、试听合成、参考音频、情绪控制、单次文本上限。界面按声明渲染，不按引擎名判断。

语言面也是 `Capabilities` 的事实格：`languages`（能念的语言代码）、`cross_lingual`（音色与正文能不能是两种语言）、`dialects`（能念的方言）、`language_note`（覆盖比官方窄在哪）。展示分两处：`cross_lingual` 是能力，只在「能力」卡里出一枚「跨语言合成」标签、不写解释；`languages` / `dialects` 是清单，单列「支持语言」一栏，语言那一行跳过同时算方言的词（粤语），`language_note` 作该栏的副标题。`describe()` 的 `languages` 块（`codes` / `items` / `dialects` / `cross_lingual` / `note`）与界面同源。

设计音色没有平台音色 id：描述存入库内音色的 `payload.design_prompt`，网关透传给插件，每次合成按描述重新生成；平台不保存音色。它不绑定引擎——描述是自然语言，凡声明了 `voice_design` 的引擎都能按它生成，用哪台由用户在合成页选。库里的这一行与普通音色同表（`voices`），只是 `folder` 为空、`payload` 里多这一句；左栏因此单独分出一组「设计音色」。创建窗口不问引擎：各家都只是「按描述现场生成」，只取哪台声明了能力，来源优先记成生成页已勾选的那台。描述可由对话模型现写（`POST /voices/design-prompt`，提示词在 `usecase/voice_design.py`）：创建窗口拿名称与已写的描述作输入；创作页由音色分配在同一次回复里直接写出最终描述，落库前只做清洗与截断；用户自己写的描述视为定稿，不改写。

### 5.2 音色通道

「这台引擎使用哪些音色、如何供给」由通道配置决定，默认值由能力推导：

| 通道 | 语义 | 默认用于 |
|---|---|---|
| `own` | 引擎有自有音色清单或克隆；入库后与本地音色统一管理，合成使用平台音色 id | 有 `voice_listing` 的引擎 |
| `library` | 引擎无自有音色；合成时以参考音频 + 参考文本提供音色库中的音色 | 无 `voice_listing` 且有 `reference_audio` 的引擎 |

允许的通道是能力的子集，越界或非法值回落到默认通道。用户修改存入 `config.channels[key]`，与 `config.engines[key]` 分开保存，避免保存密钥时覆盖通道。默认值不落盘。

### 5.2.1 音色凭据（谁决定这次发什么）

一条音色落到某台引擎上，这次请求带什么由 `app/domain/credential.py` 的 `credential_of(voice, engine_key)` 判定，结果是四种之一：

| 凭据 | 含义 | 出现条件 |
|---|---|---|
| `reference` | 带一段音频，引擎按它复刻 | 本地音色；复刻音色（`payload.ref_audio`）；跨平台且有样例的平台音色 |
| `design` | 带一句描述，引擎现场设计 | 设计音色（哪台引擎都能用，能力不够的那些由 `engines_for_voice` 筛掉） |
| `platform` | 带平台音色 id | 预置音色回到自己的平台 |
| `none` | 落不到这台引擎上，发请求之前报错 | 跨平台又没样例；本地音色没样例 |

两条硬规则：

- **预置音色一律发平台音色 id**，不拿它自己的样例去复刻；通道配置不改变这一条。
- **样例是通用素材**：别的平台留下的音频，任何接受参考音频的引擎都能拿来复刻。

这是唯一判定。网关按它组装请求，分配弹窗按它给候选（`engines_for_voice` 只多一道"就绪"过滤），前端按下发的 `voice.engines` 摆选项——生产者与前端不得自行按 `capabilities()` 再推一遍，否则选项会与合成分叉。一致性由 `tests/test_credential.py` 的矩阵锁住。

### 5.3 生成物归属

- 生成物按音色归档：`<保存目录>/<音色名>/<时间戳>-<序号>.<格式>`，同目录 sidecar 记录 `origin.voice_id`。
- 读回时先按 id、再按名称匹配；平台音色与本地音色的生成物都挂回各自音色，不新增同名条目。
- 每台引擎可单独配置保存目录（`config.engine_outputs[key]`）；留空时使用全局生成目录下的引擎子目录。
- 引擎保存目录不作为扫描根。若用户把生成目录指进音色库，扫描时跳过该目录，避免重复条目。

### 5.4 参数映射

每台引擎在 `mapping.py` 中声明统一参数到原生请求体的映射：

- `ParamMapping(source, target, required=, transform=, note=, warning=)`；
- 缺省项不发送（`skip_empty`），以区分「未要求」与「要求为 0」；
- 必需项缺失时在装配阶段报错；
- 无法换算的值报错，不静默丢弃；
- 无落点的项由 `unsupported()` 返回原因，界面显示「—」。

## 6. 合成请求

统一请求为「一段文本 + 一个音色 + 一组参数」。完整字段、单位、区间与候选见 [request-spec.md](request-spec.md)。

- 规范定义在 `domain/request_spec.py`，`GET /api/v1/spec` 下发；前端按规范渲染表单，新增参数不改前端。
- 语言、静默、输出三组在界面上默认收起，值照常生效。
- 正文支持统一语气词标记：`[[笑]]`、`[[停顿:0.4]]`。各引擎通过 `mark_map` 登记自己支持的标签；翻译由网关在发出前统一执行一次（`EnginePlugin.prepare_text`），不支持的标签在那里从正文删除。「通用」分组由核心按所有支持标签的引擎取交集，认任意标签的引擎按全集计入。
- 读音替换在网关内完成：`pronunciations.json` 提供「词 → 同音词」，按最长词优先替换，方括号标记不参与。替换只作用于发给引擎的正文，归档与字幕保留原文。

### 持久化模式

`POST /api/v1/synthesize` 的 `persist` 决定音频去向：

| 值 | 行为 | 使用方 |
|---|---|---|
| `none`（默认） | 不落盘；响应体为音频字节，元数据在 `X-VoiceHub-Meta` | 第三方调用 |
| `cache` | 落缓存目录，返回 `audio_url` | 生成页扇出 |
| `sample` | 落该引擎的音色保存目录，并登记为该音色的样例 | 音色详情的「生成样例」 |

## 7. 语音识别

识别是与 TTS 方向相反的插件域，契约在 `engines/asr_base.py`：`transcribe` / `readiness` / 能力自描述。

- **识别插件 `qwen3_asr`**：连接一台 Qwen3-ASR 服务（默认 `http://127.0.0.1:18999`）。插件只包含客户端实现，模型与服务由用户自行部署；核心不下载权重。
- **识别插件 `sense_asr`**：连接一台 SenseVoice-Small 服务（audio.cpp 的 `sense_asr` 族，默认 `http://127.0.0.1:18102`）。与 Qwen3-ASR 共用 OpenAI 兼容客户端；注意 offline 的 `sense_asr` 需要 Silero VAD 资产，默认用 streaming 的 `sense-asr`。
- **输入**：非 WAV 音频先由 ffmpeg 转为 16 kHz 单声道 WAV，再以 multipart 上传。不使用流式接口。
- **能力**：文本恒有；语种检测可选。情感、声音事件、逐词时间轴不声明，界面如实列出「不支持」（SenseVoice 模型带事件/情感标签，但当前 HTTP 结果不返回）。
- **语言清单**：由各插件自行登记（Qwen3-ASR 30 种语言 + 22 种中文方言，SenseVoice 21 种），面板按清单渲染。
- **应用层选项**（`config.asr_options`）：自动识别、写回样例、录音自动转写、语种写回。开关仅在当前引擎声明对应能力时出现。
- **自动识别的前置**：所有自动识别（连接时补逐字稿、缺逐字稿时自动识别、录音后自动转写）先过 `usecase/asr.unavailable_reason()`——与设置页「引擎状态」同一判据；批量补全另加一次 `reachable()` 探测（与「测试连接」同一个调用），服务连不上就不起线程，只留一行日志。
- **连接时自动识别**（`auto_on_connect`，默认关）：识别服务可用时（启动、保存引擎设置、测试连接成功、切换引擎），后台把库里 `samples.text` 为空的样例逐条听一遍并写回，**一直补到没有为止**。每批 200 条、批间重新查库；写回后文字非空，不会重复识别。界面用 toast 显示进度，`POST /asr/fill/cancel` 可停（当前这条收尾，不再开始下一条）。
- **语种写回**：仅当该样例为主样例且音色语言为空时写入；已有值不覆盖，非主样例只回显。
- **输入约束**：识别接口只接受「音色 id + 文件名」，路径由服务端拼接。麦克风语音输入听完即删；参考音频录音存 `<数据目录>/recordings/`，服务重启清空。

## 8. 对话模型

对话模型独立于 TTS 引擎：请求为消息数组，返回消息与用量。内置 `deepseek`：

| 项 | 取值 |
|---|---|
| 模型 | `deepseek-flash`、`deepseek-v4-pro` |
| 上下文 | 1M |
| 思考 | `thinking` + `reasoning_effort`，可按请求覆盖 |
| 视觉 | Flash 支持内容块（图片/文件），Pro 仅文本 |
| JSON | `response_format: json_object`；字段级 Schema 降级并在 `notes` 中说明 |
| 错误 | 401 / 402 / 404 / 422 / 429 / 5xx 分别报出 |

插件不支持的能力不硬发：降级与截断原因写入 `ChatResult.notes`，随响应返回。自检与模型清单的失败返回 `200 + ok:false`；补全失败返回 400。

## 9. 生产方插件

生产方拥有「书」的数据与处理流程，其他能力调用宿主：

- 项目、章节、行、角色映射、任务存插件自己的 SQLite；逐行音频与成品存项目目录。
- 分析调用 `usecase.llm`，合成调用 `usecase.gateway`，不直接持有密钥。
- 路由挂在 `/api/v1/producers/<key>`；前端按 `web/src/producers/<key>/` 懒加载工作区，宿主不出现插件名。
- 设置 → 插件是生产方唯一的入口：一张卡装一个插件（图标、名称、版本、启停状态、说明），卡上可直接打开工作区；声明了配置 schema 的插件在卡内展开「设置」，表单照 schema 画，画哪几组由插件的 `settings_page_groups` 声明。设置页不再为生产方单开分组。
- 启用 / 停用生产方：停用是服务端状态（`config.json` 的 `producers_disabled`），启动时不构造该插件的服务、不跑它的自动启动，接口一律拒绝；重启也不会自己起来。导航收起只是它的结果。项目、配置与成品都保留，随时可以再启用；启用时立刻构造服务，audio.cpp 开着自动启动就在这一刻拉起实例。

当前内置 `audiobook`（导航名「创作」）与 `audiocpp`（导航名「audio.cpp」，属工具型工作区、不声明流水线步骤）：实例地址与模型 id 取自**引擎设置里的服务地址**（不另存端口表），且只列**模型已装在本机**的实例（引擎里配了地址不等于这里有服务；跑着的服务仍会列出，免得藏掉别人的进程）；用内置运行包或用户指定的 audio.cpp 程序拉起，装第一台模型时没有可点的实例，安装动作会先按引擎地址拉起一台空实例；模型清单取自上游 `model_specs`，安装/停止/删除转发实例自己的 `/v1/ui/models/*`。拉起的实例带 `ui` + `ui_management`（0.9.4 起 native model manager 编进运行时），所以实例行给「界面」入口，用户也能在它自带的 WebUI 里装模型；插件是一台实例一个模型、靠进程隔离，不用 audio.cpp 单进程多模型那套 LRU 卸载（`--max-loaded-models` / `--idle-unload-ms` / `--min-free-memory-mb`，默认全关）。实例行**没有**「接入」这个动作：那些端口本来就是引擎在用的地址，VoiceHub 合成时连的就是它们；服务在别处（换了机器或端口）时才用服务卡底部的「其他地址」做一次只读接入，断开即回到实例视图。数据模型、阶段、状态与失效规则见 [audiobook-flow.md](audiobook-flow.md)。

## 10. API

### 约定

- 前缀 `/api/v1`，无别名。
- 集合响应：`{"object": "list", "data": [...], "has_more": false}`；单资源带 `object`；删除返回 `{"id", "object", "deleted": true}`。
- 分页：`limit` / `offset`，默认 `limit=0` 表示不分页；`limit>0` 时 `has_more` 由多取一条判定。
- 压缩：非回环来源启用 gzip（正文 ≥ 1 KB），本机请求不压缩。
- 错误体：`{"error": {"message", "type", "code", "param", "request_id"}, "detail"}`；`type` 为 `invalid_request_error` / `not_found_error` / `engine_error` / `internal_error`。响应带 `X-Request-Id`。

## 11. 前端

### 布局

主区同时只有一个视图：音色库、生成页、引擎面板、生产方工作区、日志、设置。左栏负责切换与范围选择。

- 音色库：左栏为「全部音色 / 各引擎音色层 / 设计音色 / 扫描根分类 / 引擎」。设计音色是一条跨引擎的来源，形态与目录条目一致（点一下只看这一组），标识另设：一枚圆角小牌里放 ✦，与引擎的方形图标、扫描根的线框文件夹相区分；`?source=` 的查询**排除**设计音色（它们只归自己那一组，也不计入任何引擎的条数），「全部音色」的总数则是本地 + 各引擎 + 设计音色三部分之和。左栏选中在每一页都标出来（淡底 + 左沿一道实色 + 字色转强调），生成页也标——那一列音色卡筛的就是这一组。音色卡只报样例数，不再挂引擎名（来源由左栏分组与详情头回答）。主区为筛选栏与卡片网格；右侧为详情抽屉（增删都在这边：设计音色的「移除」是详情右上角那颗垃圾桶，生成页不摆删除）。
- 生成页：左列音色卡，列头是一条「参考音频」功能条（录音 / 顺序播放 / 使用设计音色）；点卡即选中，并用它自己的主样例作参考音频（卡片右端的「选样例」才开详情挑别的一条）。中间写正文、标情绪、勾引擎，右列调参数。参考音频不单占一段：选中的音色连同那条样例置顶冻结在左列头上，卡片列的播放键放的就是这段参考。冻结卡与普通卡同一副长相（头像、名字、性别、设计标签、样例数都一样，末端多一颗「换样例」），另盖一枚斜置的朱砂「参考」印（绝对定位、不占行高；朱文单线、隶书，框贴着字走，两处缺墨由 SVG 蒙版真挖空）。印章**不看有没有样例**：它表示的是「这次用这条音色配音」，设计音色与临时录音同样盖。置顶的强调取印章的朱砂（一层淡底 + 左沿一道），不取强调色——强调色是列表里「选中」的语法，同一个音色在下面也亮着，同色就得猜哪一处才算数。悬停与选中的强调一律走底色与字色，不走边框——这一列已贴成一整块面板，行间那条细线是结构线。列表按整张卡翻：卡高由可视高均分（`--rail-card-h`），停手时由 `scroll-snap-type: y mandatory` 把落点对到卡边，因此不会停在半张卡中间；`scroll-snap-stop` 不设成 `always`，否则一个手势只走一张，长列表翻不动。
- 生产方工作区：左列音色卡片；中间是步骤条与正文；右列是章节目录。音色管理与合并收在行表上方最右侧的一颗按钮里，界面由插件自己摆。
- 引擎面板：主区页面而非弹窗，页签与表单由插件声明。
- 筛选条件（搜索、性别、年龄感、语言、标签、显示已隐藏）存入 `localStorage`，恢复发生在首次拉列表之前。

### 大列表

音色库可能有数千条。列表按三层减速，缺一层都会在主线程上看出来：

- 卡片分帧挂载：首屏 48 张，之后每帧补 48 张，加载期间界面仍可滚动、可点。
- 屏外卡片 `content-visibility: auto`，跳过排版与绘制；`contain-intrinsic-size` 按默认密度估算，渲染过的行记住真实高度。
- 封面统一走 `/cover/{id}?s=thumb`：首次请求把原图缩成 160px WebP 缓存进 `<缓存目录>/covers/`。头像原图 0.5–1MB，缩略图约 8KB；原图地址只留给"换头像 / 看大图"。
- 卡片上的性别控件只在点开时挂浮层（`v-if`），几百张卡不常驻 Teleport 与全局监听。

### 主题

设计令牌定义在 `web/src/settings/theme.css` 的 `:root`，深色覆盖 `[data-theme='dark']`，组件只引用变量。

外观分四套（`data-look`），默认原色：

| 值 | 名称 | 特征 |
|---|---|---|
| `classic` | 原色 | 冷灰底、白色面板、冰蓝强调、小圆角；全部表面为实色，无渐变、内高光、模糊与发光投影 |
| `paper` | 纸墨 | 米纸底、墨色字、朱砂强调、衬线标题、小圆角、无模糊 |
| `celadon` | 素瓷 | 冷白瓷面、青釉强调、大圆角、柔和阴影、无模糊 |
| `glass` | 玻璃 | 半透明面板、背景光、`backdrop-filter`、可调模糊与圆角 |

主题模式（浅色 / 深色 / 跟随系统）由 `store/shell.js` 写入 `<html data-theme>`，首屏内联脚本在绘制前恢复，避免闪烁。

外观主题里还可以收起主导航：`data-nav-auto` 让导航不占列宽、鼠标移到左边缘或键盘聚焦时滑出；`data-nav-labels` 只留图标。两项都只作用于桌面，窄屏导航横排在顶部。头像的显示与「头像匹配」（来源顺序、候选、裁切）同在外观主题，不再单开一组。

### 状态与验证

`web/src/store/` 按域拆分（library / engine / synth / asr / shell），各域导出的函数合并为统一 `actions`；播放器为全局单实例。

验证手段：

| 脚本 | 内容 |
|---|---|
| `pytest` | 后端单元与接口测试 |
| `scripts/smoke.py` | 接口冒烟，逐条报告失败 |
| `scripts/shot.mjs` | 无头浏览器界面自检与截图，校验服务端当前产物、页签与表单渲染、主题对比度等 |
| `scripts/make_demo.py` | 生成演示音色库，覆盖分类、多样例、单样例与平台音色 |

## 12. 运行与数据

| 项 | 规则 |
|---|---|
| 端口 | 默认 `17865`；`--port` > `VOICEHUB_PORT` > `config.json` |
| 监听 | 默认 `127.0.0.1`；`--host` > `VOICEHUB_HOST` > `config.json` |
| 数据目录 | 启动脚本默认设为 `./data`；可用 `VOICEHUB_DATA_DIR` 指定。未设环境变量而直接调用库时回落到 `%LOCALAPPDATA%\voicehub` |
| 单实例 | 同一数据目录只允许一个服务进程（`data/service.lock`）；第二个实例直接退出 |
| 配置写入 | 整份原子替换（`atomic.write_json`）；并发保存与坏文件回落仍未加固 |
| 生成目录 | 全局 `output_dir`，每台引擎可用 `engine_outputs[key]` 覆盖 |
| 缓存 / 日志 | `cache_dir` / `log_dir`，空则位于数据目录下 |
| 时长探测 | 优先使用配置的 ffprobe，其次随包 ffmpeg，最后 PATH；全格式合并与混音依赖 ffmpeg |

服务为单机个人工具：不提供用户体系；开放局域网时建议配置访问令牌，并在前面加一层带鉴权的反向代理。
