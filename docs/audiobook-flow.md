# 有声书流水线

> 内置生产方 `app/producers/builtin/audiobook/`，导航名「创作」。本文描述当前的数据模型、阶段、状态与成品规则。
> 设计总览见 [design.md](design.md)，合成参数见 [request-spec.md](request-spec.md)。

## 1. 数据与目录

### 1.1 存储

| 内容 | 位置 |
|---|---|
| 项目、章节、行、角色音色映射、任务 | `data/producers/audiobook/projects.db` |
| 原稿副本 | `<项目目录>/source/<书名>.txt` |
| 章节正文副本 | `<项目目录>/chapters/NNN_标题.txt` |
| 逐行音频 | `<项目目录>/audio/<章节 id>/` |
| 章节成品、字幕、BGM 版 | `<项目目录>/merged/` |
| 项目根 | 项目创建时记录；改设置只影响新项目 |

项目根默认位于生产方设置的项目目录下，按项目名建子目录；重名时追加序号。数据库是正文与状态的权威，磁盘上的章节文本是可读副本。

### 1.2 表

| 表 | 关键字段 |
|---|---|
| `projects` | `id`、`name`、`author`、`kind`（`book` / `subtitle`）、`folder`、`pattern_key`、拆句选项 |
| `chapters` | `id`、`project_id`、`ordinal`、`title`、`text`、`stage`、`audio` |
| `rows` | `id`、`chapter_id`、`ordinal`、`kind`、`speaker`、`text`、`emotion`、`params`、`start_ms` / `end_ms`、`audio`、`audio_key`、`audio_key_v`、`error`、`status`、`speaker_edited` / `emotion_edited` |
| `voices` | `project_id`、`speaker`、`engine`、`voice_id`、`voice_name`、`sample_file`、`sample_mode` |
| `jobs` | `id`、`kind`、`state`、`total` / `done` / `failed`、`cancel_requested`、`owner`、`heartbeat_at` |
| `row_claims` | 行级合成占位：`row_id`、`owner`、`claimed_at` |
| `analysis_cache` | 分析结果缓存 |
| `row_qc` | 回读预检：`row_id`、`audio_key`、`verdict`、`detail`、`engine` |

行身份使用稳定 id；章节顺序用 `ordinal`。合并按行序，不依赖文件名。

## 2. 阶段

### 2.1 导入与分章

**导入格式**：`.txt` / `.md` / `.markdown` / `.epub` / `.mobi` / `.azw3` / `.azw` / `.prc`；`.srt` 创建字幕项目。

**分章**：

- `.epub` 按书内目录成章：书名用 nav / NCX 的目录名（层级拼成「第一部 第二章」），
  目录没收的页退回首个 h1–h3，再没有才叫「第 N 章」；`linear="no"` 与导航页本身不入正文。
- `.mobi` / `.azw` / `.prc`（MOBI7）按 `<mbp:pagebreak/>` 分章；没有分页标记时取最上层、
  至少出现两次的 h1–h3 作标题。都没有就不硬切，留给「分章」选模式。
- `.azw3` 优先读 KF8 正文：每份 skeleton 是一个原始 XHTML 文件，fragments 按 FRAG 索引
  插回骨架；组合文件（MOBI7 + KF8）的 KF8 索引损坏时退回前面的 MOBI7 正文。
  脚注与坏源清洗与 EPUB 走同一个解析器。
- 脚注：引用标记（`[1]`、上标数字）连同前面那格空格去掉；定义块（`epub:type="footnote"`
  / `endnote`）整块不念。指向别的文件的链接是正文里的交叉引用，照旧保留。
- 坏源清洗：控制字符、替换符 `�` 一律清掉；TXT 里没被解析掉的 `<p>` / `width="2"` 残片
  也清掉（Markdown 保留，它可能本来就写 HTML）。替换符代表**已经丢掉的字**——清掉只是
  不再念出方框，补不回来，遇到大面积残字应当换源。
- 版权页、目录页这类非正文页在 EPUB2 里没有语义标记，只能靠文件名猜，猜错就是删正文，
  因此不自动删；章节在目录栏可以单章删掉。
  `.md` 有足够标题时按大纲切分；其余按所选模式逐行匹配。
- 支持内置模式与自定义正则；预览与执行使用同一套计算，预览不写库。
- 分章会替换章节与行，已有音频与成品随之失效。
- 长文本在分章前可执行两段文本处理：查找替换、整段删除。自定义正则限制嵌套量词与正文长度。
- 「删除匹配」这组预设**表序即全选时的应用序**，整行删除（`[1] 注释…` / `[注1] …` /
  `①…` / 纯标点行）排在局部删除（`[1]`、`[注1]` 只摘记号）之前：记号先没了，整行就再无锚可认，
  注释文字会被念出来。手动勾选仍按点击顺序，所以勾选顺序自己说了算。
  「移除纯标点行」要求**整行到行尾都只有标点与空白**：`***`、`.......`、`……`、`——`
  这类分隔与情绪行整行删；行首标点后面还接着正文（`……他不知道。`）不算，一个字都不动。
  EPUB 里没带 `epub:type` 标记的注释段（只是 `<p class="Footnote">`）导入时认不出来，
  就靠这几条整行预设删。

### 2.2 拆句

**选项**：

| 选项 | 取值 | 说明 |
|---|---|---|
| 拆分模式 | 按句 / 按段落 / 不拆 | 不拆 = 整章一行，也即章级生成 |
| 识别对白 | 开 / 关 | 关闭后整篇按旁白处理 |
| 引号写法 | 中文双引号 / 英文双引号 / 「」 / 『』 / ‘’ / 自动 | 混用多种引号时建议指定一种 |
| 单行字数上限 | 默认 200 | 按句、按段落模式生效，不跨段合并 |
| 短旁白阈值 | 默认 4 字 | 低于阈值的旁白并入上一句 |

**规则**：

- 台词优先、只切不改字。`老人说道：“你来了。”` 切成旁白「老人说道：」与对白「“你来了。”」。
- 引号内有句读（`。；？！` 或 `，、：`）才判为台词；术语、引文、行内强调、紧贴文字的引号留在旁白。
- 引号未闭合按旁白处理。
- 拆句只写两个占位说话人：`旁白` 与 `对话`；真实姓名由分析阶段回填。
- 重拆时文本未变的行保留说话人、情绪与音频；对不上的行作废并计数。

**行编辑**：

- 光标落在行内（点行内空白、点进文本格都算）即可「删除」这一行、「合并」它与下一行，不必先点行号；选中多行时按选中范围执行。勾选行号不构成光标：勾选是批量操作的选择集。光标随行失效——行被筛掉或被删之后，「合并」不再指向它，点行上的控件（行号、角色、情绪、音频按钮）也不留下光标。
- 「自动合并」把**短于字数上限**的旁白行并入下一行，累计到达上限即停止吸收；对白行一律不参与（并进去就换了说话人）。上限是「短」的判据，不是合并后的天花板：下一行本身较长时合并结果会超过上限。逐章执行；合并沿用行合并的后果：旧音频作废、章节退回拆句。

### 2.3 分析

使用对话模型推断每行的说话人、情绪与引导指令。

| 设置 | 默认 | 行为 |
|---|---|---|
| 分析通道 / 模型 | 默认通道 | 来自 `app/llm` 插件 |
| 分析范围 | 全部对白 | 或「只补未标注」，只处理仍写着「对话」的行 |
| 发送粒度 | 按批 | 每批默认 120 行；或整章一次 |
| 上下文 | 整章正文 | 或本批前后各 N 行（默认 80） |
| 并发 | 4 | 上限 16 |
| 分析提示词 | 说话人+情绪 | 预设：说话人+情绪 / 说话人+引导指令 / 说话人+引导指令+情绪 / 精简 / 保守认人；预设正文在「设置 → 词表 → 对话分析提示词」里改 |
| 标注内容 | 由提示词决定 | 无单独开关：预设身份决定要回哪几格；自定义提示词写了「引导指令」就解析指令，同时写了「情绪」就两个都解析 |

弹窗选中的预设只存键（`analysis_preset`），正文在分析时取设置页的生效值：
在设置里改了预设，所有选它的项目下一次分析立刻跟着用。弹窗里直接改正文则存成本项目的
`analysis_prompt`，只影响这个项目。AI 匹配音色、角色画像与文本转正则的系统提示词/模板
也在同一处「词表」里编辑，各功能读取同一份生效值。

**处理规则**：

- 旁白行不参与匹配，模型不能改写旁白。
- 请求不跨章；超过通道回复上限时自动对半分段，不整批失败。
- 回复为紧凑数组 `[[行号, 姓名, …内容…, 原文前 6 字]]`：除说话人外的值按内容认，
  词表里的算情绪、其余算引导指令，所以模型把两格的顺序写反也不串格；
  多出来的一格当回显，对不上就丢弃并计数。
- 回显不符的条目丢弃并计数。
- 已出现的角色名随批次累积，尽量保持同一叫法。
- 情绪只接受生效词表中的值；词表外的值不写入，只在报告中列出。
- 引导指令写进行参数（`instruction`），与行内合成参数同一处；行里已经有一条时**不覆盖**
  （那是用户自己写的），模型只补空位。超过 60 字截断，外层引号与换行先清掉。
- 引导指令按「情绪基调 + 念法」合成一句（如「压抑的怒气，压低嗓子一字一顿地说」），不超过 20 字，
  语言与原文一致，不写成叙述句、不重复原文。理由是有引擎只认这一路：情绪与引导指令各有落点时
  情绪不发送（见 [request-spec.md](request-spec.md) §4.5），指令是唯一的表演信息通道。
- 结果按「内容 + 通道 + 模型 + 提示词 + 温度 + 契约版本 + 上下文 + 情绪词表」缓存；解析失败的响应不写缓存。
- 可重试错误重试一次；密钥错、参数错不重试。
- 人工改过的说话人 / 情绪带 `*_edited` 标记，后续分析不覆盖。

**行表显示**：情绪列在行内有引导指令时默认显示引导指令，表头的胶囊按钮可在
「情绪 / 引导」之间切换；引导指令一格单行截断，点开就是这一行的参数弹窗。

### 2.4 生成

**输入**：已标注的行、角色 → 音色映射、引擎。

**角色音色**：

- 每个角色指定引擎、音色与样例策略：`emotion`（按行情绪匹配样例）或固定某条样例。
- 匹配使用同义词表；没有对应情绪的样例时使用主样例。
- 无样例的平台音色只能由其所属引擎合成；有样例的音色可供给任意接受参考音频的引擎。
- 本地音色的 id 跟着目录路径走：目录移动后旧 id 失效。每次扫描完成后按「唯一同名 + 原引擎可用」自动把项目的旧引用重绑到新 id；同名歧义或找不到的留在分配弹框里手动重选。重绑不改音频文件；旧指纹仍对得上的行会把音频键换到新 id，不会被判成过期。
- 「音色管理」弹窗顶部两栏可切换：**音色分配**是一张可编辑的分配表，每个角色一行，引擎、方式（预置音色 / 参考音频克隆 / 音色设计）与具体音色都能手动改。音色格是可输入的下拉：打音色名、标签或语言就筛出相近候选，不做「交给 AI 挑」的空选项；每行末尾的星星让 AI 只重挑这一行，顶部的「AI 匹配」只补还没选音色的角色。已指定音色的角色同样能打开调整，应用时才会覆盖。「音色设计」那一格留空也能点 AI——描述由模型按角色画像现写并随提案一次返回，用户填了则以用户那句为准。**角色合并**把重名的说话人并成一个角色，角色摆成标签多选，与分配共用同一个窗口尺寸，切换栏目不跳宽窄。
- 从左栏音色卡打开的「指定音色」弹窗：角色按**未指定 / 已指定**两栏台账排列，行数跟在角色名后，试听是行末一整格高；某一栏为空时整栏收起，不留空列。已指定的行写着它现在的音色，有样例就能直接试听；选中已指定的角色时按钮改说「覆盖」。本地音色没有引擎认它时，引擎栏写「没有可用的引擎」并禁用按钮，不拿「本地音色」冒充引擎名。
- 旁白也占一行：引擎、方式、音色、样例照样能改，音色写入 `voices['旁白']`，旁白行（`speaker` 为空或为「旁白」）随它一起换。它不是书里的角色，AI 匹配不处理它，音色格只留试听按钮。
- 还没识别出角色、只剩拆句留下的「对话 / 未知」占位时，分配表改成一行一章，表头写**章节**：每章一颗引擎、方式与音色，不参与 AI 匹配。第一次只为某一章指定时，其余章沿用这颗音色；之后再改一章只改这一章，别的章保持原样。章级音色写入 `chapter_voices`，只在这本书没有具名角色时生效；出现具名角色后分配表回到按角色、读取 `voices`。同一状态下从左栏「指定音色」打开的弹窗也按章列行（表头写「章节」），选中某一章指定，首次指定时其余章沿用，之后再改只改这一章。
- 入口只有一颗「音色管理」按钮，摆在行表上方的最右侧；工作区右列是章节目录，左列整列归音色卡片。
- AI 分配时写下的角色描述取画像里的 `note`（身份、年龄感、说话方式；没有 note 才用一句分配理由），存进 `voices.reason`（最长 300 字），角色栏每次打开都显示；**它属于角色而不属于某一颗音色**——换引擎、换音色、改样例都保留，只有 AI 重新写一句才替换。
- 「AI 匹配」分两段：先取一份声音画像（性别、年龄、音色质感、语气、语速）——只发书名（带作者）与角色名，不发对白、不发候选；书名取项目名并去掉版本与来源标记，作者取书目信息，写成「《书名》（作者 著）」。再按画像在全库做向量检索，每个角色保底几条，全局收到 40 条交给模型裁决。没有向量模型时退回「有样例、收藏优先」的名字顺序取 200 条。画像这一步可以声明平台的服务端联网搜索：认不准的角色模型自己查、自己整合，宿主不执行工具循环；平台只返回纯文本，正文不是 JSON 时再补一次纯 JSON 抽取。作者已经随书名给出，不需要模型去查。认不准的标为未知，那一行按名字匹配。画像按书名 + 作者 + 角色名缓存（`cache/voice_profiles.json`）。
- 试听按钮播的是**这一行选中的那条样例**（固定样例）；只有「按情绪匹配」时才播主样例。
- 分配表里滚轮只滚列表、不改值：引擎、方式、音色、样例都要点开后再选，滚过去不会悄悄换掉。
- 未选时优先本地引擎与参考音频克隆，云端引擎用预置音色。
- 设计音色每次合成按描述重新设计，平台不保证两次一致；需要稳定音色用参考音频复刻。

**预检**：未映射角色、空台词、超过引擎 `max_chars`、已有音频的行。预检返回报告，不创建任务。

**合成**：

- 逐行请求；并发按引擎自己的设置：云端引擎用引擎设置里的「合成并发」，
  直接生效，不受项目「合成并发」影响；单模型本机服务（audio.cpp 的 GGUF 实例）声明硬上限 1
  （并发不会更快，只会让每行都等更久）；没有自带并发设置的引擎才用项目设置。
- 云端引擎同时受「每分钟请求数」约束：平台限的是 RPM，不是并发数。每条请求都先过
  `app/engines/ratelimit.py` 的闸口（并发位 + 滑动窗口），跨任务、跨项目共享；
  平台回限流时整台引擎降温后退避重试，不逐行判死。
- 排队**按音色分块**：同一个角色的行连着生成，模型不必每行重载一次参考音频；
  块内仍是章序 / 行序。
- 音频指纹用 v2：文本 + 引擎 + 引擎身份（插件版本 / 模型 / 后端）+ 音色 + 情绪 + 样例 +
  行级参数 + 该行实际命中的读音替换。输出格式不再进 v2 键（容器由引擎决定）；老行按 v1
  比对，对得上只换键、不重做，对不上才重新生成。
- 合成前先 `claim_row` 抢行级占位；抢不到说明另一批正在写这一行，直接跳过。
- 响应通过魔数与最小长度校验后才落盘。
- 单行失败写入 `error` / `status='failed'`，保留旧音频与 `audio_key`，任务继续其余行；可按行重试。只有参数改动产生的 `stale` 行可通过 `_settle_stale` 自动恢复，失败行不作自动恢复。
- **引擎连不上就停这一台**：错误码 `engine_unreachable`（连接被拒）一旦出现，本轮不再给该引擎
  发请求，剩余行留在「待生成」且不写 `error`——服务没起时逐行重试只是白撞，还会把行表刷成满屏失败。
  原因写进任务 `message`；其他引擎照常跑完。
- 任务状态存 `jobs`；取消在批次与行之间生效；进程重启把残留 `running` 标为 `interrupted`。
- **启动只扫一遍**：全项目的行一次 join 取回（不是逐章查），计划算完直接带进任务；
  「文件还在不在」按目录列一遍、章阶段用 `chapters()` 里的行统计判，不逐行 / 逐章回查。
  进度与取消按 0.4s / 0.2s 节流后落库，收尾强制刷一次——一万五千行若逐行 UPDATE，
  写锁会把合成本身拖慢。

### 2.5 合并

- **本章**：按行序拼接，插入行间静音与章节前后静音，统一重编码。
- **全部章节**：逐章合并**还没合并**的章节；已合并与没有音频的章节跳过，中途失败后再点一次只补剩下的。同一项目同时只跑一路合并，重复提交报忙。
- **格式**：M4A（AAC）/ MP3 / WAV，默认 M4A 128k；M4A 带 faststart。
- **标签**：专辑=书名（用户改过就是改后的值，不用源文件名），标题=章节名，序号=章序从 1 起，专辑艺术家=作者，作曲人=本章实际用到的引擎（按首次出现去重，`、` 连接），备注=来源地址（`SOURCE_URL`，未配置时退成 `audiobook:<项目 id>`）。`artist` 不写：它是"演唱者"，填引擎名会被书库当成一位艺人。空值不写。M4A / MP3 写全；WAV 的 RIFF INFO 没有专辑艺术家与作曲人两个字段，这两项在 WAV 成品里写不进去。
- **字幕**：合并时按逐行音频实际时长生成 SRT / LRC；长对白按 32 字切 cue。
- **BGM**：开启后另出 `<成品名>-bgm.<格式>`，原声版保留。曲目从目录**随机抽取**，一曲放完接下一曲，直到铺满本章人声长度（不循环单曲，一轮内不重复，曲库不够再洗一轮）。每曲先按 EBU R128 拉平响度，再按设置增益混入；`bgm_gain_db` 是相对人声的增益，不是绝对 dBFS——开启响度标准化时 `-20 dB` 约等于旧脚本 `-35 dBFS` 的绝对电平。淡入淡出与章节前后静音同长，人声起时已经到位。重跑一次会换一套抽签结果。
- **合并前检查**：存在 `stale` 行时拒绝合并，要求重新生成或改回原样；若开启「疑似行阻断合并」（`qc_block_merge`），章节存在预检 `suspect` 行时同样拒绝合并。
- **成品自检**：比对实际时长与「字幕时间轴 + 章尾静音」；量不到记为未检查，只报告不阻断。
- **导出**：全部章节合并后导出 ZIP（包名即书名，无后缀），每章只放一份最终音频——开了 BGM 且有混音版就放混音版，否则原声，两版不并列。条目名为 `序号-章节名`：三位序号按章节顺序给出（排序靠它，也是唯一性来源），不带书名、不带 `-bgm` 后缀；SRT / LRC 跟随同一份成品一起打包。另有整本 M4B 导出：章节内嵌、带 faststart，手机有声书播放器可直接跳章。

### 2.6 预检

检查已生成的行音频，按「声学前置检查 → ASR 回读比对」顺序执行，可在预检弹窗分别勾选。**旁路**：只读行音频、只写 `row_qc`——不进音频指纹、不改行状态；是否阻断合并由用户开关（`qc_block_merge`）决定。

- 触发：生成任务标完终态后自动衔接（设置里「生成后预检」）；或在预检步骤卡上手动跑。
- 任务 `kind='qc'`、`exclusive=0`：不占「同一项目同时只跑一个任务」的名额，合并与生成不必等它。
- 只检指纹变过的行，或本次新勾选了此前未跑过的检查步骤的行；已覆盖所需步骤且指纹对得上就沿用旧结论。
- **声学前置检查**（`qc_acoustic`，不依赖识别引擎）：检查静音/无声、尾音截断（末尾能量未衰减）与时长异常（过短/过长）。
- **ASR 回读比对**（`qc_asr`，最后一步）：比对在**无声调拼音的音节序列**上做，不在字上做：同音字（`医院` / `医愿`）算一致；数字段整体折叠成一个记号，逐位读、口语读、阿拉伯数字三种写法等价。
- 判档：静音、尾音截断、时长异常、漏读（缺失连续 ≥3 音节，或缺失比例 >10%）、多读（凭空补出的非语气词 ≥2）、整句走偏（5 音节及以上替换比例 >25%；2–4 音节短句替换 ≥2 且 >40%；单字不以单音节替换判疑似）、长度对不上（差 >50%）。其余为一致。
- **测不出多音字读错**：识别输出的是字，字定读音，反推的拼音已丢掉声学信息。那一路仍靠读音替换表与人工试听。
- 仅开启 ASR 且识别引擎不可用时整批跳过，原因写进任务说明，不建空任务；同时开启声学检查时自动降级为只跑声学检查；单行识别失败记 `unknown` 并继续。
- 结论与那一版音频的指纹绑定，换引擎重生成后自动作废，不需要清理。

## 3. 状态与失效

### 3.1 行状态

| 状态 | 含义 |
|---|---|
| `text` | 有文本，未分析 |
| `analyzed` | 已标注，无有效音频 |
| `audio` | 有有效音频 |
| `failed` | 上次合成失败，`error` 有原因 |
| `stale` | 参数已变，旧音频保留但不算数 |

章节阶段：`chapters` → `sentences` → `analysis` → `audio` → `merged`。

### 3.2 失效规则

| 改动 | 行 | 章节 | 旧音频 |
|---|---|---|---|
| 重新分章 | 重建 | `chapters` | 删除 |
| 改章节正文 | 重建 | `chapters` | 删除 |
| 拆句 / 重拆 | 重建或复用 | `sentences` | 文本未变的行保留 |
| 改说话人 / 情绪 / 文本 / 行参数 | 更新 | `analysis` | 标 `stale`，保留 |
| 换角色音色 | 更新 | `analysis` | 标 `stale`，保留 |
| 合并角色 | 更新 `speaker` | `analysis` | 标 `stale`，保留 |
| 重新分析 | 更新 | `analysis` | 标 `stale`，保留 |
| 合并行 / 自动合并 / 拆分行 / 删除行 | 结构变化 | `sentences` | 作废，不保留 |

### 3.3 过期音频的恢复

`stale` 行保留 `audio` 与 `audio_key`。读取详情、章节、编辑结果、开始合成与合并前，`_settle_stale` 会按当前参数重算指纹：

- 指纹与原记录一致，且音频文件仍存在 → 恢复为 `audio`；
- 不一致或文件已删除 → 保持 `stale`。

因此改回原来的角色、情绪、文本、行参数或音色时，不需要重新合成。合并遇到无法恢复的 `stale` 行会拒绝，避免把上一版声音混入成品。

### 3.4 统计

`chapters()` 聚合以下计数，章节灯与行表筛选共用：

| 计数 | 判据 |
|---|---|
| `unassigned` | 说话人为空或「未知」 |
| `pending` | 已定说话人、非失败、无有效音频（含 `stale`） |
| `failed` | `status = 'failed'` |
| `stale` | `status = 'stale'` |
| `broken` | 正文含替换符 / 控制字符 / 属性碎片（`rules.is_broken`；详情接口扫描正文后补进章节） |
| `suspect` | 预检判为疑似；与上面几项正交，不参与相加 |
| `done` / `analyzed` / `dialogue` / `rows` | 已生成 / 已标注 / 对白 / 总行数 |

未分配与待生成互斥：未分配的行不计入待生成。失败行按 `status` 单独计数，可能与未分配重叠；章节灯只判断是否大于 0。`broken` 是另一维，也可能与前三类重叠，只用于「需校对」这一档。

章节灯跟着行表当前选中的筛选档走：选「未分配 / 待生成 / 失败 / 需校对」时只按那一类亮灯；选「全部」时四类合看，并在悬停说明里分别列出。`broken` 只在项目详情里补算（正文扫描不进 `chapters()` 的常用查询），行接口也带 `broken`，行表筛选与章节灯用的是后端同一句判据。

行表的「状态档 + 角色」是一整条筛选链（`web/src/producers/audiobook/visible.js`）：表格显示的行、章名旁「逐行试听」的播放队列、章节栏里被排除的章（`is-absent`）与章名上的滚轮换章都读同一份结果。筛了角色或状态后，试听播的是眼前这一批行；滚轮换章只停在还留有匹配行的章上（当前章按已加载的行实时判，其余章按上表的聚合计数），到头停下、不绕回。被排除的章整行压暗并划掉章名，与可用的章一眼分得开。

## 4. 角色与音色

- 角色名单来自 `detail.speakers`：只包含正文中实际出现过的说话人。
- 角色的 `kind` 与 `speaker` 同步：旁白为 `narration`，其他为 `dialogue`。
- 「音色管理 → 合并」把多个名字统一为目标名，只改 `rows.speaker` 并置 `speaker_edited`；旧音频标 `stale`，章节回到分析阶段。`voices` 表中的旧映射保留但不显示。
- 换角色音色会让该角色所有行失效；目标角色没有音色时，生成前检查直接报错。
- 「指定音色」把角色摆成可换行的标签：已指定 = 实心强调色点 + 淡强调描边，未指定不加点。
  标签上不写音色名；行数与"配了谁"留在悬停和读屏文字里。打开时**不预选角色**，点一个才能点「指定」。
- 每个生产方记住**最后打开的项目**（浏览器本地存储 `vh-producer-project:<key>`）：
  重新打开创作页、或在主页播放条上「指定音色」，用的都是这本书的角色，而不是列表第一本。
  记的那本被删掉时才回落到列表第一本。

## 5. 字幕项目

字幕项目是单章项目，`projects.kind = 'subtitle'`，行上带 `start_ms` / `end_ms`。

**导入**：读取 SRT，每条字幕一行，保留时间码与文本；带说话人标记时填入 `speaker`，否则留「对话」交给分析。原始文件另存于 `source/`。

**合并**：与书稿项目相反，时间码是硬约束：

- 按绝对时间点排布：音频短于时隙时补静音；长于时隙时顺延，并把后续条目标记为 `delayed`。
- 可选「变速贴齐」：仅加速、不拉长；上限内贴得进去才变速，超过上限的条目整条顺延。
- 字幕按实际时间轴写出，不切 cue、不重排。
- 不同采样率的片段统一重采样后拼接，避免时长偏移。

## 6. 设置

设置页（「设置 → 插件 → 创作」）只放目录一项；其余参数跟着使用它们的步骤卡走，改完即保存、随即执行。

| 位置 | 项 |
|---|---|
| 设置 → 插件 → 创作 → 项目 | 项目目录 |
| 创作 → 语句拆分（拆句选项） | 拆分方式、单行字数上限、对话引号 |
| 创作 → 对话分析 | 通道、模型、提示词、范围、发送粒度、每批行数、并发、上下文范围与行数 |
| 创作 → TTS 生成 | 合成并发、生成后预检 |
| 创作 → 合并音频 | 合并格式、成品码率、行间静音、章节前/后静音、SRT / LRC、变速贴齐与最大倍率、BGM 开关与目录、BGM 音量、音量标准化 |

字段仍由 `settings.py` 的 pydantic 模型声明；设置页按 `ui_hints` 的 `group` 渲染，工作区卡片读同一份 schema 的候选与默认值，前端不维护字段名单。设置页画哪几组由插件的 `settings_page_groups` 声明，依赖项的可用条件由 `enabled_when` 声明，不满足时置灰并说明。

## 7. 任务与错误

- 分析与生成是后台任务：`POST /steps/{analysis,audio}` 返回 202 与任务 id；`GET /jobs/{id}` 查询进度；`POST /jobs/{id}/cancel` 请求取消。
- 同一项目同时只允许一个任务；有任务运行时拒绝新的分析与生成。
- 同一数据目录只允许一个服务进程（`data/service.lock`）；第二个实例直接退出，避免两批任务写同一行。
- 失败信息只呈现上游原话：引擎连不上、缺密钥、平台返回的错误码原样显示，不翻译、不概括。
- 单行失败不中断整批；任务结束后可按行重试。

## 8. 待办

- **提示语是否参与合成**：`老人说道。` 目前单独成旁白行并由旁白音色念出。可选方案：保留但不送合成，或并回相邻台词行。
- **引号跨段**：连续多段对白中，每段开头有 `“`、只有末段有 `”`。当前按未闭合处理，整段归为旁白；后续可按段落继承引号状态。

## 9. 验证

后端测试覆盖以下不变量：

- 拆句只切不改字；各行文本合计等于章节正文（忽略换行）。
- 分章、拆句、分析、生成的状态流转与失效范围。
- 音频指纹变化与 `stale` 恢复；文件不存在时不恢复。
- 合并拒绝 `stale` 行；章节计数与行表筛选一致。
- 字幕项目的时间轴、顺延与变速贴齐。
- 任务状态、取消与重启后的 `interrupted` 标记。
- 预检比对：同音字归并、数字三种读法等价、漏读与静音分档、语气词不计入多读。
- 预检任务不占独占名额；结论随 `audio_key` 变化自动失效。
