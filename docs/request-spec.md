# 合成请求规范

> 本文定义 VoiceHub 对外合成的统一请求：一次请求 = 一段文本 + 一个音色 + 一组参数。
> 规范只定义字段、单位与取值；字段如何落到某家引擎的请求体，由该引擎目录下的 `mapping.py` 决定。
> 实现位置：`app/domain/request_spec.py`（规范）、`app/engines/mapping.py`（映射机制）。

## 1. 边界

- 本层保证字段可被界面采集、可被请求体携带；某台引擎是否支持某一项，由该引擎的映射表说明。
- 不支持某项时，在映射表里写原因，界面显示「—」，不从规范中删除该项。
- 参数名使用本服务的命名，不对应任何一家的 API。翻译与换算在接收侧完成。

## 2. 请求总表

| 组 | 字段 | 中文名 | 类型 | 单位 | 取值 | 必填 | 说明 |
|---|---|---|---|---|---|---|---|
| 路由 | `engine` | 引擎 | str | — | 已安装引擎的 key | 是 | 由哪台引擎合成 |
| 文本 | `text` | 正文 | str | — | 非空 | 是 | 可含语气词标记 |
| 音色 | `voice_id` | 音色 id | str | — | 库内音色 id | 是 | 定位音色；参考音频由音色样例带出 |
| 音色 | `reference_audio` | 参考音频 | str | 路径 | 存在且可读 | 否 | 不传 = 使用音色主样例；传 = 覆盖这一条 |
| 音色 | `reference_text` | 参考文本 | str | — | — | 条件 | 参考音频的逐字稿；由样例自动带出，是否必填由引擎声明 |
| 音色 | `emotion` | 情绪 | str | — | 词表候选，可手输 | 否 | 这一句的语气 |
| 合成参数 | `instruction` | 引导指令 | str | — | 一句自然语言 | 否 | 描述音色或念法 |
| 合成参数 | `guidance_scale` | 指令强度 | number | — | 0–1，默认 0.5 | 否 | 引导强度 |
| 合成参数 | `speed` | 语速 | number | 倍率 | 0.5–2.0 | 否 | 1.0 = 原速 |
| 合成参数 | `volume` | 音量 | number | 倍率 | 0.2–2.0 | 否 | 1.0 = 原音量 |
| 合成参数 | `pitch` | 音高 | number | 倍率 | 0.5–2.0 | 否 | 1.0 = 原音高 |
| 合成参数 | `seed` | 种子 | int | — | -1 或 0–2147483647 | 否 | -1 = 每次随机；走 `extra` |
| 静默 | `lead_silence` | 前静默 | number | 秒 | 0–10 | 否 | 本段之前 |
| 静默 | `lag_silence` | 后静默 | number | 秒 | 0–10 | 否 | 本段之后 |
| 语言 | `language` | 正文语言 | str | — | BCP-47 主语言子标签 | 否 | 正文所用语言 |
| 语言 | `reference_language` | 参考语言 | str | — | 同上 | 否 | 参考音频所用语言 |
| 输出 | `format` | 格式 | str | — | wav / mp3 / flac / pcm / ogg / aac | 否 | 空 = 未指定 |
| 输出 | `sample_rate` | 采样率 | int | Hz | 16000 / 24000 / 32000 / 44100 | 否 | |
| 输出 | `bitrate` | 码率 | int | bps | 32000–320000，步进 8000 | 否 | |
| 专有 | `options` | 专有参数 | dict | — | 引擎声明 | 否 | 采样参数等 |

`engine` 与 `persist` 是接口字段；上表其余项来自 `SPEC_FIELDS`（界面与参数映射页的规范清单）。`reference_text` 是请求字段但不在 `SPEC_FIELDS`：它由样例的说话内容带出，不单独占参数映射页的一行。

**可选字段的含义是「未要求」，不是「使用默认值」。** 缺省字段不发送；`0` 与不写不同：`lag_silence: 0` 表示明确不留空。

## 3. 界面映射

- 总表的分组即界面分组；分组、控件、单位、区间、默认值由 `GET /api/v1/spec` 下发，新增参数不改前端。
- 语言、静默、输出三组默认收起；收起不改变取值。
- 数值项默认使用滑块，起点为该字段的默认值；未拖动时不进入请求，界面显示「默认」角标。种子是整数输入，不是滑块。
- 文本类长字段使用带预设的文本框；预设由插件通过 `field_presets` 提供。
- 情绪为「候选 + 手输」组合框：候选来自生效词表，词表外可输入，由引擎决定是否接受。
- 语言、格式为固定取值下拉。

## 4. 逐组说明

### 4.1 文本

- 上限由引擎声明的 `max_chars` 决定；本层不截断，超限直接报错。
- `text` 同样参与映射：不同引擎可能使用不同键名（如参考文本 `prompt_text`），语气词标记也在这一步处理。
- 文本可包含统一语气词标记，见第 5 节。

### 4.2 音色

两种取音色方式对应两类能力，不是同一个字段的两种写法：

| 方式 | 适用 | 说明 |
|---|---|---|
| `voice_id` | 有平台音色清单的引擎 | 使用平台音色 id |
| `reference_audio` + `reference_text` | 接受参考音频的引擎 | 音色即参考音频本身 |

- `voice_id` 定位库内音色；平台音色走平台 id，本地音色由核心把主样例填进 `reference_audio` / `reference_text`。
- 预置音色（平台清单里的那些）一律走平台 `voice_id`，即使它手上有样例也不拿去复刻；样例只用于本地音色、复刻音色与跨平台借用。判定见 [design.md](design.md) §5.2.1。
- `reference_text` 是否为必填由引擎的 `synthesis_spec().requires` 声明；GPT-SoVITS v3/v4 必填。
- 界面上的「参考音频」列出当前音色已有的样例：不选 = 使用主样例；选某一条 = 使用该样例的声音与语气。
- 「参考音频」与「情绪」不互斥：两者都给时一并发送，由引擎决定采用哪一个。

### 4.3 合成参数

- `speed` / `volume` / `pitch` 为倍率，无量纲；`lead_silence` / `lag_silence` 为秒。
- 不同引擎的量程与表示不同，换算在映射表中完成。例如 MiniMax 的 `pitch` 为半音，按 `12 × log₂(倍率)` 四舍五入到整数。
- `instruction` 与 `guidance_scale` 成对使用：前者描述念法或音色，后者控制引导强度。
- `guidance_scale` 统一为 0–1；引擎自身的量程（如 CFG 0–8）由映射表换算。它控制强度，不控制是否生效。

### 4.4 语言

- 使用 BCP-47 主语言子标签：`zh` / `yue` / `en` / `ja` / `ko` / `es` / `fr` / `de` / `ru` / `pt` / `it` / `ar` / `nl` / `tr` / `uk` / `id` / `vi`。
- `language` 与 `reference_language` 分别描述正文与参考音频；引擎只有一格时，由映射表说明取哪一格。
- 未提供时使用引擎配置中的默认值；音色的语言标签可作为默认值来源。

### 4.5 情绪

- 默认词表三组：基础情绪 开心 / 悲伤 / 愤怒 / 恐惧 / 惊讶 / 兴奋 / 委屈 / 平静 / 冷漠；
  复合情绪 怅然 / 欣慰 / 无奈 / 愧疚 / 释然 / 嫉妒 / 厌倦 / 忐忑 / 动情 / 害羞 / 疑惑 / 失望 / 担忧；
  态度 严肃 / 轻蔑 / 恳求 / 得意 / 撒娇。
  基础那一组与 MiMo 官方的基础情绪表逐字一致；词表可在设置中增删，分组只影响界面摆法。
- 「态度」是**对人或对事的姿态**，与语调不是一回事：语调是角色的整体特征（挂在音色上），
  情绪是这一句怎么念（进合成参数）。整体活泼的角色照样可以有严肃的一句，所以两处可以
  同时出现同一个词（如「严肃」），各自生效、互不覆盖。
- 入选标准：**这个词能不能改变这一句的念法，且现有词改变不了同样的东西**。只靠语义
  区分、念法上落回既有词的不进候选。
- 旧写法（难过 / 生气 / 害怕 / 中性…）由 `app.domain.emotions` 归一到上面的规范词，
  老数据照常出声；「中性」「厌恶」不归一——前者等于"没有情绪"，后者与任何规范词都不等价。
- 映射到引擎枚举时，无法识别的词从该字段剔除，其余参数照常发送，并在结果 `notes` 中说明。
- 情绪是可选参数；单个词不被识别不应导致整段请求失败。
- 情绪与引导指令**各有原生落点**的引擎一次只发一路：带引导指令时 `emotion` 不发送。两路风格同时下给引擎，引擎各让一半，读法反而失真；引导指令更具体，故以它为准。没有引导指令时情绪照发。落点相同的引擎（把情绪翻成引导指令的那类）不适用本规则。判据取映射表，不按引擎名分支，见 `EnginePlugin.dual_expression()`。

### 4.6 输出

- `format` 为空表示调用方未指定，由引擎按配置决定；本层不填默认格式。
- `sample_rate` / `bitrate` 可选；未指定时使用引擎配置。

### 4.7 引擎专有参数

- `seed` 是统一字段（`SPEC_FIELDS` 里有这一格），但走 `extra` 传递：`-1` 表示每次随机，由插件抽成非负整数并写回 `notes`。
- 各家的采样参数（`temperature`、`top_k`、`top_p`、`repetition_penalty`、`text_split_method` 等）放在 `options`。
- `options` 的键由该引擎的映射表读取；未声明的键不会进入请求体，也不参与换算。
- 专有参数不进入通用总表，避免为每家的采样细节定义无意义的统一区间。

## 5. 语气词标签

### 5.1 语法

```
[[标签]]          例：[[笑]]
[[标签:参数]]     例：[[停顿:0.4]]
```

标签名为中文，参数为秒。解析与翻译在 `app/domain/marks.py` 中实现，各引擎只登记 `mark_map()`。

### 5.2 翻译规则

- 每台引擎登记自己支持的标签 → 原生写法。
- 不支持的标签在装配时从正文删除。保留会被当作文字念出。
- 翻译由网关在发出前统一执行一次（`EnginePlugin.prepare_text`，见 `app/usecase/gateway.py`）；插件不各自调用，写法随正文变的引擎（BreezeTTS 按中英换括号）重写该方法。
- 删完之后正文为空（整段只有一个标签）时报错，不发空台词。
- 标签键用统一的中文含义（`MARKS` 的规范名）。照抄平台原文写法也可以：`MARKS` 的 `aliases` 在装载时归一，同一概念不会因为两种写法变成两条（`scripts/marks_audit.py` 列出未收录的写法）。
- 认任意标签的引擎声明 `mark_passthrough()`（如 MiMo，表外标签按 `(名)` 发出）。
- 引擎能力与标签表在「引擎 → 能力与参数」中列出，界面按后端下发的表渲染。

### 5.3 通用分组

- 「通用」= 所有支持语气词的引擎的交集，由核心跨引擎计算。
- 不支持语气词的引擎（空表）不参与交集。
- 认任意标签的引擎支持面按全集算：它发得出去，也不会因只登记几条而压低通用。
- 只有一台引擎支持时，交集即该引擎的标签集。
- 分组与当前勾选的引擎无关；扇出到多台时，不支持的引擎在装配阶段删除对应标签。

### 5.4 平台专属限制

平台对标签的模型门槛、位置要求等由插件在装配时守卫，并写入映射表的 `note` / `cautions`；本文不复制单家清单。

## 6. 映射现状

映射以各插件目录的 `mapping.py` 为准，界面由 `describe()` 从声明生成；本文不复制映射表快照。参数页逐项回答“规范字段有没有落点、落点在哪、怎么换算、为什么没有”，来源是同一份声明。

## 7. 实现边界

- `SynthesisRequest` 将 `text`、`voice_id`、`reference_audio`、`reference_text`、`emotion`、`format` 作为一等字段；其余参数经 `extra` 传入，由映射表按名称读取。
- `SPEC_FIELDS` 是界面与参数映射页的规范清单，不等于 `SynthesisRequest` 的字段表：`seed` 在 `SPEC_FIELDS` 里但走 `extra`，`reference_text` 是请求字段但不在 `SPEC_FIELDS` 里。
- 引擎的映射表通过 `ParamMapping` 声明落点、换算与说明；`unsupported()` 声明无落点项；`cautions` 声明跨参数约束。
- 新增参数时，修改 `request_spec.py` 与需要支持的引擎映射表；前端与 API 形状不变。
- 参数值无法换算、必填项缺失时，在装配阶段报错，不发出请求；未声明的 `options` 键被忽略。
- 失败只呈现上游原话；本层不追加解释、不翻译错误码。
