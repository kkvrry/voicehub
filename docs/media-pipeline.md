# 媒体工作流（配音）设计方案 v2

> 输入音视频，按可组合的操作产出成片与字幕。
> 本版相对 v1 的改动：固定九步改为**类型化对象 + 可组合操作**；角色成为对象；听写页并入本工作区。
> 设计稿：`docs/design/dubbing-station.html`。
> 已落地部分见 §0：「引用或上传 → 抽音轨 →（可选）分轨 → 转录 → 逐段合成
> → 贴齐 → 混音 → 导出」。变声与配乐属于变换域，尚未实现。

## 0. 已落地范围（v0.1）

导航新增「配音」（`producers/builtin/dubbing/`）。工作区三列，右列是六步状态机，
分轨是可跳过的一步，贴齐与混音共用一张卡；不建可拖拽的节点画布，步骤状态由后端算，
界面不自己推。参数与模型摆在各自的步骤卡里（识别引擎、分轨模型、合成并发、贴齐与导出），
字段归属由设置 schema 的 `step` 声明。

```
引用本机文件 / 上传（音视频）
  → 抽音轨      ffmpeg 解复用，统一 44.1k 立体声 PCM
  → 分轨        可选：audio.cpp sep 分出人声与伴奏；十分钟一块，可取消
  → 转录        ffmpeg silencedetect 切段 → 逐段走 usecase/asr；有分轨时切人声轨
  → 配音        gateway.synthesize 逐段合成，产物统一 44.1k 单声道 PCM
  → 贴齐        按时间码补静音、加速贴齐，仍贴不进去的按槽位截断（usecase/assembly.py）
  → 混音        配音 / 原声人声 / 伴奏三条轨按各自电平混合，再按响度目标校准
  → 导出        视频封装 MP4（画面拷贝，可选 mov_text 字幕轨）/ 音频转 MP3·M4A·WAV
```

角色不是流水线步骤：旁白默认存在，段落表与顶部角色条分配说话人，角色决定音色；
配音卡的摘要直接带配音 / 原声 / 缺音色的段数。

与设计稿的差异，都是"当前只做有依据的部分"：

| 设计稿 | 已落地 | 原因 |
|---|---|---|
| 五条轨（原声/人声/伴奏/配音/配乐） | 三条（配音 / 原声人声 / 伴奏）；未分轨时原声人声就是整条原声 | 配乐未接入；音色不做成一条轨 |
| 九步含分轨、变声、配乐 | 六步 | 分轨已接入；变声与配乐未实现；贴齐与混音是同一个动作的两段；角色在角色条分配，不单列一步 |
| 工作流可保存、可换模板 | 单链路 | 图编辑留到有第二个链路之后 |
| 段落表就地编辑 | 已实现（行内改文本、角色与音色） | 行高固定才能虚拟滚动，所以文本最多两行、超出在框内滚 |
| 段落表虚拟滚动 | 已实现（固定行高 + 可视窗口） | — |
| 段色带 canvas | 已实现 | 2000 段不逐段建 DOM |

数据落在 `<数据目录>/producers/dubbing/projects/<id>/`：
上传导入的 `source.*`、引用导入不带源文件、`audio/{original,vocals,accompaniment}.wav`、
`work/{segments,stems,tts,assemble}/`、`out/{vocal.wav,mix.wav,bed.wav,vocals-masked.wav,成片,与成片同名的字幕}`。
项目元数据在同级 `dubbing.db`（projects / cues / roles / jobs 四张表，WAL）；
分轨的模型、标签与源音轨指纹记在 `projects.options.stems`。

实现口径：

- **时间码来自实测边界**。切段用 `silencedetect`（默认 −35 dB / 0.35 s），段落边界即字幕
  时间码；超过「最长段」的连续语音按等长硬切，而不是按字数估。
- **改一段只重跑这一段**。合成键（`_audio_key`）= 文本 + 引擎 + 引擎身份
  （`engine_identity`：插件版本 / 模型 / 后端）+ 音色 + 参数 + 样例策略 +
  **这一段实际命中的**读音替换；键没变的段第二次直接复用，
  不请求引擎。样例策略只在角色明确选过时进键；旧键没有引擎身份、用的是整张读音表
  版本，两种口径都认，旧项目不会因为升级判据整批作废。合成期间用户改过字或角色的，
  产物照写，但按当前参数重算键：对不上记 `stale`。详情里也按当前键重算
  `ready / stale`，换模型或改读音规则会直接显示「待重配」。键没变、文件还在的段
  被跳过时把 `failed` 擦成 `ready`，否则会永远停在「失败」。
- **产物是否还在磁盘上要一并回答**。详情里的 `audio_version` 是文件写入时刻，
  `audio_ok` 说明文件还在不在；文件被清理或手动删掉的行不再假装「已配音」，
  播放键置灰并写明原因。

**引用导入与上传导入是两种来源。** 上传由浏览器把字节送到临时目录再复制进项目；
引用只记绝对路径（`source_linked`），项目里只有转出的音轨与产物，预览与导出照常读原片。原片被移动、
改名或删除后项目会明确说「源文件不在了」，重新指定时只接受时长与项目时间轴一致、
且具备原音轨序号的文件——段落时间码是按原片排的。删除项目只删项目目录，不碰引用的
原片。浏览器拿不到真实路径，所以选文件必须由宿主弹本机对话框，入口只限本机。

**分轨是可跳过的一步（`STEP_MANIFEST` 的 `separate`），不改变「原声 / 配音」的语义。** 分轨后转录从人声轨切段，
静音检测不会被音乐填满。混音变成三条轨：配音、原声人声、伴奏；被配音的段只静音
原声人声，伴奏整条保留；还没分轨的项目仍是「整条原声在配音段静音」。模型只认
运行中的 audio.cpp 实例（`bs_roformer` / `mel_band_roformer` / `htdemucs` 族），
没有模型时卡片写明原因，不假装可用。分轨按十分钟一块调用、相邻块重叠半秒再切掉，
拼完校验两条轨的时长；源音轨重新抽取或重新指定后旧分轨自动失效，混音退回整条原声
并提示重跑。分轨结果不另开表，模型、标签与源音轨指纹记在 `projects.options.stems`。

角色两种处理方式：`配音` 与 `原声`。**原声的段落不进合成清单**，成片里放的就是源文件
在那一段的声音；`配音` 的段落合成之后**替换**原声——混音时先按这一段自己的起止时间码
把原声整段静音（分轨后只静音原声人声，伴奏继续；`volume=0:enable='between(t,…)+…'`，
区间多到一行命令行装不下就按窗口切开；`enable` 按帧求值，所以先 `asetnsamples=n=256`
把帧切成 256 样本，否则段首会漏出近 90 ms 原声），再与配音轨合成，同一时刻只有一个声音。静音范围不按配音音频的实际长度算：配音比原句
短时，原句剩下的部分保持静音；比原句长时按槽位截断，不越过下一段。所以：

- 没指定角色的段落归**旁白**（第一条角色），不是"随便找一条会配音的角色"；
  判据只在 `service.role_of`；转录时把归属明确写进去，不留空。
- 进度只数需要配音的段落（`stats.dubbed`），保留原声的段永远不会缺产物；
  行上的 `dub` 由后端下发，前端不自己推；`ready` / `stale` 只数产物还在磁盘上的段，
  `audio` 有值但文件没了算 `pending`。
- 三条轨的电平是混音参数，不是「要不要保留」的开关：`original_gain` 压原声人声
  （没分轨时是整条原声），`dub_gain` 压配音，`accompaniment_gain` 压伴奏；
  默认 0 dB，−60 dB 为静音。
- 字幕是整片的：配过音的段按贴齐后的位置写，保留原声的段与还没配出声音的段
  都按源时间码写。

替换与入库都先落任务目录，确认后才动库；时长偏差超过 50 ms
（`service.DURATION_TOLERANCE`）只拦替换，入库是新样例，不受这条限制。
合成单模型并发 1，同一时刻只跑一条，逐条写 `running`，取消在条与条之间生效。

界面这一侧：

- **在行内改**。文本一格，角色一格；行内弹层只换角色，音色只在主壳左栏指定，
  行内不再摆音色清单。角色弹层里只显示当前音色与「在左侧音色栏指定」这一句，
  不另摆第二份音色选择器。行尾两枚键分别试听原声与配音，两者互斥——原声走预览、
  配音走独立音轨，一边开始先停另一边。宿主播放条（音色栏试听、筛选连播）开始播时，
  预览与逐段配音也停；反过来开始这两路时先停宿主播放条。角色是「原声」时配音键
  置灰并写明这一句保留原声，不能拿改回原声前的旧配音试听；右键菜单同一判据，
  配音不可用时播源音轨的那一段。文本输入格带 `data-app-menu`：没有选区时右键交给这一行的项目菜单
  （播放 / 重配 / 拆分 / 合并 / 删除），有选区时仍走浏览器菜单。
- **编辑器以输入框里的值为准**。输入法组字期间 `v-model` 不跟输入（这是 Vue 的设计），
  这时若用 `draft` 存库，刚敲的那个词会整段丢掉——所以回车/失焦都读 DOM 值，组字中的
  回车与 Esc 一律让给输入法（`composing` / `isComposing` / `keyCode 229`，见
  `SubtitleRow.vue::onKey`）。回车保存但不离开，Esc 撤销，失焦保存。
- **轮询的旧快照不能落地**。请求发出后本地若写过库（`writeRev` 变了或在飞），那份快照
  比本地还旧，落地就把刚改的字擦回去；丢掉它、再拉一轮（`store.js::refresh / mutate`）。
  写库本身在 `store._write` 里对 readonly / locked 退避重试。合成任务里「音频已落盘、
  只是没记进库」不算合成失败（`OperationalError` 是库的问题）：否则会出现显示失败、
  播放却正常。
- **试听要带上产物版本**。逐段音频是覆盖写的同名文件，`audio_version`（mtime + 大小）
  拼进地址、媒体端点回 `no-cache`：否则重配之后点播放，听到的还是缓存里那一版。
  角色或样例一换，正在放的旧版先停下，下一次点击才是新的一版。整片试听的
  `mix_version` 同理。
- **多选点序号，不摆复选框**。行首序号本身就是选中键（Shift 连选），表头 `#`
  全选当前筛选结果；点行的其他位置仍是「选中并把播放头移过来」。多选后的批量改角色 /
  删除只走 `cues/batch`，前端不逐行发请求。
- **筛选栏的播放键**。没有筛选时直接播成片混音（`out/mix.wav`，从头到尾，
  就是导出那条声音，原声段按成片位置出现），不另起音轨；有筛选时按筛选结果
  逐段播：配音段放该段产物，原声段（包括改回原声但还留着旧配音的段）放源音轨
  的对应区间，不拿旧配音顶替。成片还没贴齐时退回逐段队列，不假装有成片。
  宿主播放器的曲目支持 `{start, end}` 截取，播放条按这一段算时长，段尾自动接
  下一段。
- **左栏小卡可右键**。音色栏里的小音色卡与冻结的参考卡共用 `voice.card` 菜单：
  打开音色卡、顺序播放全部样例、找头像、隐藏、复制音色名、复制音色 ID、移除。打开音色卡
  进音色库详情，不改变当前工作区的角色。
- **角色条横排，音色从主壳左栏指定**。插件声明 `voice_rail=true` / `rail_mode="assign"`，
  左栏的「指定」把一条音色交给角色，弹层与创作页共用同一份：目标按
  「未指定 / 已指定」两栏排，引擎按这条音色的可用声明列，本地音色还能选
  「按情绪匹配 / 固定样例」；同一条本地音色可落在多台引擎上，用户选的是用哪台
  引擎的这条声音。多选段落后可顺手把选中的段改为该角色，不必逐行点。
- **换回原音色不重配**。角色换音色时逐段重算合成键，键对得上且文件还在就恢复
  「已配音」；角色列不再用彩色圆点区分，颜色不再承担任何选择语义。
  时间轴色带的角色色按名字散列，与无封面头像同一份算法，不存进角色表。
- **点名重配不复用缓存**。行上的「重配这一段」与多选后的「重新配音」会带上
  `force=true`；工作流的「合成剩余」不带，未改动的段仍直接复用。
- **日志逐段说清做了什么**。开始时报段数、角色 / 音色 / 引擎与并发；每段报序号、
  起止、文本摘要、角色 / 音色 / 引擎、字数、耗时、产物大小、情绪、样例策略与
  引擎提示；失败报错误码、原因和旧音频是否保留；整台引擎不可用时写明触发段并
  停下该引擎的剩余段，最后汇总新配 / 复用 / 失败 / 跳过与产物总量。
- **贴齐与导出是后台任务**。`/assemble` 与 `/export` 只创建 `dubbing_job` 并立即返回，
  阶段写进 `job.message`（贴齐 / 混音 / 字幕 / 封装），`done / total` 给任务条画进度；
  取消走 `/jobs/cancel`，在阶段边界与拼装算法的检查点生效。贴齐内部不再允许
  第二个操作同时写 `vocal.wav` / `mix.wav`：同一项目有一把操作锁。
- **分轨与轨道电平在右列**。分轨步骤卡里选模型并开始；完成后显示模型与「移除」。
  底栏混音器列出配音、原声人声、伴奏三条轨，−60 dB 即静音；时间轴在分轨后多一条
  伴奏轨，原声轨改叫原声人声。
- **导出永远按当前段落重算**。点导出先重跑贴齐与混音，再封装；文件名以导出时间
  开头（`20261121-145659-项目名.mp4`），历史成品保留在项目目录。时间不放在长项目名
  之后——成品列表与资源管理器会截掉末尾，看起来还是「旧同名」。详情同时给出
  `mix_current` / `export_current`：比较「段落时间戳与项目级 `content_at` 里最新的
  一个」与文件 mtime，并比较项目上记的 `assemble_key` 与当前设置；任一项对不上
  就不再显示「完成」。改段刷新段落时间戳；拆分、合并、删除、改角色音色或处理方式、
  改任一轨音量会抬高 `content_at`；改贴齐、响度或字幕设置，以及分轨新增 / 移除 /
  换源音轨，会让 `assemble_key` 对不上。
  时间戳带微秒——删除不留段落时间戳，同一秒内改完也要显示「要重新导出」。
  旧项目还没有 `assemble_key` 时先按段落判，下一次贴齐自动补上。
  每条成品后有「打开文件夹」按钮，走本机限定的 `POST /projects/{id}/reveal`，
  按成品名定位目录。
- **字幕导入是另一条入口**。已有 SRT / VTT 时不必重新识别；VTT 的 `<v 角色>` 等内联
  标记会在导入时去掉，角色按旧段落的重叠关系继承，重叠时间码会顺延修正。
- **转录字幕本身就是成品**。转录或导入完成即按当前段落写出字幕文件，成品区直接
  列出并可下载，不必先贴齐或导出。改字、改时间码、拆分、合并、删除会同步重写；
  贴齐后按成片时间码重写。字幕媒体端点带下载头（`attachment`）。
- **字幕与当前成片同名**。`xxx.mp4` 配 `xxx.srt`，下载后播放器能自动挂上，不用
  手动改名；还没有成片时用项目名。导出时贴齐直接按新成片名写，之后改字继续用
  最新成片的名字。旧项目启动时把固定的 `subtitles.*` 改名到当前成片名下，只改名、
  不重写内容——已经按成片对齐过的字幕不能拿源时间码盖回去。历史视频保留自己的
  旧文件名，不再为每一版留一份字幕。

## 1. 修订对照

| v1 | v2 | 原因 |
|---|---|---|
| 九步顺序写死 | 操作靠端口种类连接，图是数据 | 增减一步要改代码与界面 |
| 步骤只是列表项 | 每步产出命名对象，可试听、可另存 | 「每一轮都有对象」 |
| 角色是一张表 | 角色是对象 `casting`，TTS/RVC 以它为输入 | 按角色分流要进图 |
| 听写页独立 | 并入同一工作区；纯音频不显示视频区 | 字幕编辑只应有一处 |

## 2. 对象与种类

图上的边不传「音频」，传**带种类的对象**。种类是契约的一部分，只有这九种：

| 种类 | 含义 | 形态 |
|---|---|---|
| `media` | 源容器，含流清单（音轨、字幕轨、分辨率、帧率） | 原文件 |
| `audio.mix` | 一条完整混音 | WAV |
| `audio.vocal` | 人声，单条或按段 | WAV |
| `audio.bed` | 原片的伴奏与背景（音乐、环境、音效） | WAV |
| `audio.music` | 配乐素材（生成或引入，非原片内容） | WAV |
| `cues` | 带时间码与角色的段落序列 | JSON |
| `casting` | 角色 → 处理方式与音色 | JSON |
| `track` | 贴齐后的编排：轨道、每段定位、贴合状态 | JSON + 段音频 |
| `video` | 成片 | MP4 |

三条规则：

1. **种类由核心定义，插件不得新造。** 允许插件自定义种类的代价是：A 插件的 `audio.voice` 接不上 B 插件的 `audio.vocal`，"自由组合"变成自由踩坑。加种类要改核心并迁移存量项目。
2. **种类同时决定端口、界面控件与落盘方式**，不只是一个字符串。
3. **中间件一律 WAV PCM16**：混音与配乐 44.1kHz 立体声，人声与识别副本 16kHz 单声道。不落 MP3 中间件——一个项目里会转码五六次，每次都损一点。

## 3. 操作契约

```python
@dataclass(frozen=True, slots=True)
class Port:
    name: str                 # 端口名，同一节点内唯一（vocal / bed / music）
    kinds: tuple[str, ...]    # 接受或产出的种类，按优先级排列
    required: bool = True
    many: bool = False        # 可接多路（逐段产物按 cue 归并，一段只允许一个来源）

@dataclass(frozen=True, slots=True)
class Operation:
    key: str; label: str; vendor: str; version: str
    inputs: tuple[Port, ...]
    outputs: tuple[Port, ...]
    unit: str = "whole"       # whole 整条 / item 按段、按行
    params: type[BaseModel] | None = None
    engine: str = ""          # 依赖的模型实例种类（tts / asr / timbre / stems / music）

    def run(self, ctx, src: dict[str, list[Artifact]], params, out: Path) -> dict[str, list[Artifact]]:
        """unit=item 时只处理一个单元：ctx.unit 给出 id 与内容。"""
```

**宿主负责一切非模型的事**：解码与重采样、切段与合并、缓存键、串行租约、进度、失败隔离、命名与落盘。插件只发一次请求、回一个文件。这条是「各步骤仅管输入输出」的落点——否则每个插件各写一套 ffmpeg 调用，半年后没人敢动。

内置操作：

| op | 输入 | 输出 | unit | 说明 |
|---|---|---|---|---|
| `extract` | `media` | `audio.mix` | whole | 解复用；多音轨时按流选 |
| `stems` | `audio.mix` | `audio.vocal`、`audio.bed` | whole | 分离模型 |
| `asr` | `audio.vocal` \| `audio.mix` | `cues` | item | 段级识别，优先吃人声轨 |
| `tts` | `cues`、`casting` | `audio.vocal` | item | 只处理标为 tts 的角色 |
| `rvc` | `audio.vocal`、`casting` | `audio.vocal` | item | 只处理标为 rvc 的角色，保时长 |
| `music` | — | `audio.music` | whole | 生成或引入 |
| `align` | `cues`、`audio.vocal`×N | `track` | whole | 补静音 / 加速贴齐 / 按槽位截断；按 cue 归并多路 |
| `mix` | `track`、`audio.bed?`、`audio.music?` | `audio.mix` | whole | 侧链、响度、限峰 |
| `mux` | `audio.mix`、`media` | `video` | whole | 视频流复制，软字幕 |

`tts` 与 `rvc` 都产出人声，但**端口种类不同**：一个吃 `cues`，一个吃 `audio.vocal`。这正是"每种操作定义种类来确认对象"的用处——界面不会把文本喂给变声器。

## 4. 图与工作流

- **建图即类型匹配**：为某端口挑上游，列表按 `kinds` 过滤。没有候选时端口写「缺输入」，并列出能产出该种类的操作，而不是让用户自己猜。
- **校验**：无环；单值端口只有一个来源；至少一条路能到 `video` 或 `audio.mix`；**每个段落恰好一个出处**——按 `casting` 判定，标为 tts 的段由配音节点生产、标为 rvc 的段由变声节点生产，缺处理器时报「角色「陈默」标为变声，但没有启用的变声节点」。校验在保存时执行，失败给一句可读原因。
- **角色不建并行分支**：`casting` 是数据对象，`tts` / `rvc` 逐段读它决定这一段谁来处理。两节点可以同时存在（混用：主角换声、配角重配），各自只产出属于自己的段，`align` 按 cue 归并。界面上是角色表，不是三条线——图上真实并行分支会让调度、缓存、进度同时变复杂，而收益只是画得好看。
- **工作流 = 图 + 参数默认值 + 名称**，存 `workflows` 表，可跨项目复用。内置三个：`变声重制`、`重配`、`仅字幕`。
- **切换只在同形态内允许**：`变声重制` 与 `重配` 是同形态（有配音链），可在工作流列顶部的下拉里直接换，节点状态、端口与角色归属随之变；`仅字幕` 是没有配音节点、只导 SRT 的另一种形态，建项目时选择，不在已有项目上切换——否则磁盘上已有的配音产物与「未启用」的节点会自相矛盾。
- **模板带 `schema_version`**：插件升级改了参数名，载入时按版本迁移；迁移不了就明确报「模板与当前插件版本不兼容」，不静默套默认值。没有这一条，「可保存工作流」半年后全是废纸。

内置链路（同一套操作，开关不同）：

```
变声重制（默认）：extract → stems ─┬→ asr ─┬→ rvc（陈默 42 段）──┐
                               │       └→ tts（其余 135 段）─┼→ align → mix → mux
                               └→ bed ─────────────────────┘
重配：        extract → stems ─┬→ asr → tts（214 段）────────┐
                               └→ bed ───────────────────────┴→ align → mix → mux
仅字幕：      extract → asr → cues                      （导出 SRT，不走配音）
```

`mix` 还可再接 `music` 的产物；不接就是没有配乐。

## 5. 执行

```python
def run_node(proj, node):
    src = {p.name: [artifact(e) for e in edges_into(node, p)] for p in op.inputs}
    base = digest(op.key, VERSION, node.params, [a.fp for a in flat(src)])
    if (hit := cache.whole(base)):
        return hit                                  # 整条命中，零成本
    with lease(op.engine):                          # 每实例一把，默认 1
        if op.unit == "whole":
            return op.run(ctx, src, cfg, out) | cache.put(base)
        for unit in units(src):                     # 段或行
            k = digest(base, unit.id, unit.fp)
            got = cache.get(k) or op.run_one(ctx, unit, cfg, out)
            cache.put(k, got, commit_each=True)     # 逐单元落盘，可断点续跑
```

- **租约**：每个模型实例一把，默认并发 1。图上并行的两条分支不会同时压同一张卡。之前靠「步骤顺序」约束，现在图是自由的，必须由调度层保证。
- **缓存**：产物键 = 操作 key + 版本 + 参数 + 输入指纹；单元级再加单元 id 与内容指纹。改一段文本只重跑这一段，其余命中。
- **失效**：上游指纹变化时，下游产物保留但标 `stale`，界面灰显并给「重跑」。只有用户删产物才真删文件。
- **失败隔离**：单元失败不进整体失败；节点状态 `partial n/m`，可只重试失败单元。
- **取消**：当前单元收尾后停，已完成产物保留。

## 7. 界面

一页到底，三栏三区：

```
┌ 导航 ┬ 配音 · 项目 · [模板 变声重制 ▾] ──────────── 引擎 · 另存为工作流 · 导出 ┐
│      │ 源 + 角色 288 │ 预览（16:9，字幕叠加三档）    │ 工作流 300             │
│      │               ├──────────────────────────────┤ 每步：端口映射、状态、   │
│      │               │ 下区：[时间轴 | 字幕] 切换     │ 产物；底部导出          │
└──────┴───────────────┴──────────────────────────────┴────────────────────────┘
```

中列只有上下两块：上为预览，下为**一块共用区域**，用「时间轴 / 字幕」切换，默认字幕——配音的日常动作是改字与听音。下区高度可拖，也可一键占满整列；只看片时切回时间轴。预览下常驻走带（播放、时间、进度条），进度条与画面同宽。

- **字幕视图是编辑的唯一入口**：下区切到「字幕」，行内改文本、点角色 chip 换人、拖时间码微调；失焦即提交，只重跑那一段。切回「时间轴」看排布与进度，两者不并列。这就是原先听写页的编辑器。
- **预览叠加三档**：`关 / 文本 / 文本 + 角色`。只影响预览；导出是否烧录是另一个开关。改字幕时开着「文本 + 角色」，按空格播放，边听边改。
- **工作流列**：列头是一个模板下拉（不是三个按钮）与节点数；每行显示名称、端口映射（`mix → vocal + bed`）、状态、产物入口。不可用的操作置灰并给一行原因（「未安装 timbre 实例」）。下拉换模板即换整张图的状态，不需要二次确认。
- **加一步**：只列出"输出种类能接上当前缺口"的操作——类型系统在界面上的唯一体现，也是它与节点画布的分界。
- **纯音频项目**隐藏视频区，段落表与导出不变：一次拖入即出 SRT。

## 8. 性能

段数决定渲染方式。12 分 30 秒约 214 段，30 分钟约 500 段，两小时约 2 000 段。

| 段数 | 每段一个 DOM 块 | 结论 |
|---|---|---|
| ≤ 300 | 约 1 200 节点 | 直接渲染 |
| 300–800 | 约 3 200 节点 | 缩放、拖拽开始掉帧 |
| 800+ | 1.2 万节点以上 | 必须换策略 |

两条硬规则：**概览走 canvas，DOM 只留可视窗口**（段宽 < 6px 时不建元素）；**播放头只改 `transform`**，播放时 rAF 读 `video.currentTime`，暂停即停。

七条口径：波形由服务端算 2 000 个峰值；段色带 canvas 每列取色；段块窗口化（左右各留一屏）；段落表固定行高虚拟滚动（常驻 ≤ 40 行，聚焦行才变输入控件）；`cues` 用 `shallowRef` + 版本号；拖拽 `pointerup` 才提交；进度只写日志，界面按批合并一次渲染。

## 9. 风险

| 风险 | 说明 | 处置 |
|---|---|---|
| 图过于自由 | 用户连出跑不通的图，或语义正确但结果荒谬 | 保存时校验；运行前预演（列出将执行的节点与预计时长） |
| 模板腐化 | 插件升级后旧模板失配 | `schema_version` + 迁移 + 明确报错 |
| 同卡争用 | 并行分支同时要 GPU | 实例租约；界面显示「排队中」 |
| 分离残留 | 人声轨残留伴奏，转换后成噪声 | 暴露质量参数；不达标提示换更强模型 |
| 逐段请求放大 | 2 000 段 = 2 000 次调用 | 单元级缓存 + 断点续跑 + 批量节点（P1） |
| 磁盘 | 原件 + 每节点产物 + 逐段音频 | 「清理中间产物」只留 `out/` 与 `cues`/`casting` |

## 10. 分期

| 期 | 内容 |
|---|---|
| P0 | 内置两模板可跑：extract / stems / asr / tts / align / mix / mux；casting；段落表；三段中区 |
| P1 | 图编辑（加删节点、重接端口）、工作流保存与载入、`rvc`、`music` |

## 11. 验收

- 关掉 `stems`：`asr` 自动改吃 `audio.mix`，链路仍能跑到 `video`，界面不报缺输入。
- 把某角色从 tts 改成 rvc：只有该角色的段重跑，其余段命中缓存。
- 改一段文本：该段产物失效，其它段与 `stems` 不重跑。
- 载入 v1 时期保存的模板：或迁移成功，或明确报不兼容，不静默改参数。
- 2 000 段项目：拖动播放头与缩放时主线程 ≥ 50fps，段落表可视行 ≤ 40。

## 12. 我的意见

关于这份修订，有六点与"完全自由"不同：

1. **底层真图，界面不做节点画布。** 端口拖拽、连线合法性、自动布局、框选缩放，实现成本约为线性工作流列的 3–5 倍；而实际用法 90% 是两三条固定链。类型化的"槽"已经给出组合能力，画布留到 P2，且只在高级模式出现。
2. **种类必须封闭在核心。** 开放自定义种类看似灵活，实际会让两个插件无法对接，且迁移成本随项目增长。宁可加种类时改一次核心。
3. **角色走数据，不走分支。** 每个角色一条并行边，图会从 7 个节点膨胀到 20 个，调度与缓存都要重做。角色表 + 逐段读表，效果相同，代价小一个量级。
4. **合并听写页要有前提**：纯音频项目必须保留"一次拖入即出 SRT"的轻路径，否则日常最高频的小任务被重流程拖慢。导航项可以去掉，入口不能只剩重流程。
5. **模板不版本化就等于没有工作流。** 这一条不做，P1 的"保存工作流"会在第一次插件升级后全部失效。
6. **`tts` 与 `rvc` 不要合并成一个"声→声"操作。** 前者吃文本与角色，后者吃音频与参考音色；强行统一，界面就无法判断该给哪个端口喂什么，"每种操作定义种类"也就失去了意义。
